FancyMenu · UI rework concept · rules, continued

Fix during the rework

Bugs we found while making these mockups, and changes that come with the rework. The numbers continue from the rules on the board above.

54Line-break markers stay out of saved text
One-line values save line breaks as %!n!% and the spaces after them as %!s!%. Those markers end up in saved layouts, value previews and copied text, and every place that uses such a value has to strip them again.
See: Text editor · today and proposed. Fixed by rule 69: Keksuccino/FancyMenu#1860
55Toast titles without markers
A line break typed into the title of a Show Toast action leaves %!n!% in the toast, because the title never gets the markers removed.
See: Text editor · today and proposed. Fixed by rule 69: Keksuccino/FancyMenu#1860
56HTTP bodies keep their line breaks
The body of a Send HTTP Request action is saved as a one-line value, so its line breaks get deleted: a JSON body loses all its formatting, and "a", a new line and "b" get sent as "ab".
See: Text editor · today and proposed. Fixed by rule 69: Keksuccino/FancyMenu#1860
57Write File can write \n
Write File saves line breaks as the text \n and turns them back into line breaks when it runs, so it can't write an actual backslash followed by n.
See: Text editor · today and proposed. Fixed by rule 69: Keksuccino/FancyMenu#1860
58Dragging scrolls up too
While dragging an entry in the action script editor, moving above the list never scrolls it up, because the check compares the pointer’s x position with the list’s top y position. Dragging close to the left edge of the window scrolls up instead, anywhere in the list.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1852
59Folders and comments move like other steps
Move Up and Move Down, and Shift+↑/↓, do nothing for folders and comments in the action script editor. The menu entries are active, but the entry stays where it is.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1853
60A While runs again after a timeout
A While loop that hits its 3 second timeout once is skipped on every later run until FancyMenu reloads, because its timeout flag is only reset by a run that finishes in time. A timeout only stops the run that hit it.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1854
61Added and dropped steps land in the same place
Adding a step to a selected block puts it at the end of the block, while dropping one on the block puts it at the start. Both put it right below the block header.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1855
62Cancel only asks when something changed
The action script editor asks whether to discard everything on Cancel and when its window closes, even when nothing changed. It only asks when there are changes to lose.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1856
63Requirements become Conditions
Everything the UI calls a requirement is called a condition, all over FancyMenu: Loading Requirements becomes Loading Conditions, Manage Requirements becomes Manage Conditions, requirement groups become condition groups, and Requirement Caching becomes Condition Caching. The condition editor goes along, so texts like Edit Requirement Value, This requirement has no value and You need to edit the requirement value first! talk about the condition and its variables instead (rule 66). That's about 140 texts in en_us.json, plus the same ones in every other language file. The conditions themselves keep their names, like Is Singleplayer. Saved identifiers keep "requirement", so old layouts keep loading. Class names and the API can be renamed along with it, since addons are allowed to break (rule 49).
See: Script editor · today and proposed, where If and While already talk about conditions
64Action variables get types
Every action takes one string today, so many of them pack several settings into one text, like intro_seen:true for Set Variable or url|||POST|||{…} for Send HTTP Request. Each action can split it into variables, each with a type from the same enum as placeholder variables, plus a sentence for its row in the script editor (rule 65). Set Variable gets Variable and New value, Play Audio gets Sound, Volume and Channel. The editor then shows the right control for every variable, the same way as for placeholders. Actions that don't declare variables keep one text variable with the raw value, and saved values stay as they are.
See: Script editor · today and proposed. Variable types: Keksuccino/FancyMenu#1849
65Everything describes and registers itself the same way
Placeholders, actions, conditions and listeners all get a display name, a description and a category from one shared list, plus a display name, description, type, default and example for every variable. Listener Variables get all of that except a display name, because people type them as $$key_name and the UI shows exactly that. Their texts are plain localized strings found by a key convention, instead of Components with formatting codes, so the UI can search, sort and style them itself. All four share one registry base with the same registration rules, and the same job gets the same method name in every kind, like one method for whether an entry shows in the editor. Actions and conditions also get a row sentence with a slot for each variable, like Set Variable {variable} to {value} or {variable} is {value}, so the script editor shows every step in words in every language, in whatever word order the language needs, with the slots as tokens. Conditions get a second sentence for Is Not, like {variable} is [not] {value}, where the brackets mark the words to highlight. Variables left out of the sentence only show in the form. A step without a sentence shows its name followed by its variables, and registration warns about slots that aren't variables.
Full plan: Keksuccino/FancyMenu#1857
66Values become variables
What placeholders, actions and conditions take as input is called a variable, not a value, everywhere. In the editors, Edit Action Value, Configure Value, Value: and This action has no value talk about variables, and the same goes for conditions. Descriptions too, like the Required values:, Optional values: and Values: lists of placeholders, or Takes the key of an effect as value. Every language file follows. In the API, getValueNames, hasValue, hasRawValue, getValueDisplayName, getValuePreset, getValueFormattingRules and editValue make way for the variable definitions, and the values map of DeserializedPlaceholderString becomes the shared variables object. The placeholder string writes "vars" instead of "values" and still reads "values", so old layouts keep working. What listeners hand to their scripts are Listener Variables. A variable still has a value, so phrases like the value of a variable, or names like Is Variable Value and Possible Values: 0-100, stay.
See: Text editor, Script editor · today and proposed. Plans: Keksuccino/FancyMenu#1849, Keksuccino/FancyMenu#1857
67One clean system for $$ names
$$name reads something by its name: a Listener Variable like $$old_value, a FancyMenu variable like $$coins, or $$value, the current value of a Checkbox or Slider. That last one isn't a variable, so these are element values, and the UI names them after their element, like Checkbox value. In the code, ValuePlaceholderHolder, addValuePlaceholder, getValuePlaceholders, applyValuePlaceholders and the two separate "$$" constants drop the placeholder name and become one shared resolver for $$ names. Listeners and elements hand their names to the context a script or condition runs in, instead of copying them into every action, block and condition like today. Texts stop calling them placeholders, like the '$$value' placeholder in the Checkbox and Slider descriptions. At every $$ the longest matching name wins, so $$item_key never eats the start of $$item_key_count, and $$ works in every text, also in ones without a placeholder. Both go wrong today.
See: Script editor · today and proposed. Plan: Keksuccino/FancyMenu#1857. Bug reports: Keksuccino/FancyMenu#1858, Keksuccino/FancyMenu#1859
68New variables can't take $$ names
Wherever someone names a new FancyMenu variable, like Manage Variables, Set Variable, the linked variable of Checkbox, Slider and Input Field, or the response variable of Send HTTP Request, names that Listener Variables or element values use, like old_value, player_name or value, are refused, and the field says what uses the name. Old layouts, /fmvariable from a server and addons that add new listeners can still bring such a variable, so it keeps working: Get Variable reads it by name, Manage Variables marks it, and when both have the same name, $$ always picks the Listener Variable or element value, so $$old_value in a listener script always means the listener's variable.
Plan: Keksuccino/FancyMenu#1857
69Typed line breaks are stored one way
Every text property says whether it's one line or multi-line and holds real line breaks, and only the layout file escapes them, in one place. One-line values keep the line breaks and indentation people type, and FancyMenu joins them in one single place when the value gets used, instead of %!n!% and %!s!%. %n% and a typed \n stay text codes, because variables, placeholders and server data use them to make line breaks. Old layouts convert per property, the way each one uses its markers today, so the same text comes out. The Toast title and message, the Write File content and the HTTP body become multi-line, and old HTTP bodies keep sending as one line. This fixes rules 54 to 57.
See: Text editor · today and proposed. Plan: Keksuccino/FancyMenu#1860
70Steps can be turned off
Every step in the script editor gets a Runs switch, and Ctrl+/ turns the selected steps on or off. A step that's off stays where it is, dimmed with an Off chip, and the script skips it, like commented-out code. Turning off a block, like If, While, Folder or Delay, skips everything inside it. Turning off an If also skips its Else If and Else, while turning off a single Else If or Else only skips that branch. The layout saves one extra line for each step that's off, so old layouts load with everything on (rule 49).
See: Script editor · today and proposed
71Collapsing is view state
Collapsing a block in the script editor isn't an edit. It's still saved with the layout, so a script opens the way it was left, but Undo and Redo skip it, and it doesn't count as a change, so Cancel doesn't ask about it (rule 62). Every branch collapses on its own: collapsing an If only hides the If's own steps, and Else If and Else get their own collapse arrow and saved flag. In old layouts, a collapsed If opens collapsed, and its Else If and Else open expanded.
See: Script editor · today and proposed
72Variable actions get shorter names
The display names of Set Variable Value (FM Variable), Delete Variable (FM Variable), Clear All Variables (FM Variable) and the Is Variable Value (FM Variable) condition become Set Variable, Delete Variable, Clear All Variables and Is Variable Value in every language file, matching Get Variable (rule 51). Their identifiers stay the same, so layouts keep working.
See: Script editor · today and proposed
73Element settings describe themselves
Every element setting, the shared ones included, becomes a property that knows its value, default, type, choices, range, unit, step, help, section and the setting it depends on. Context menus build their rows from that alone, which is what rules 17, 18, 20, 25 and 26 need: the value on the row, the reset arrow, Mixed, switches, sliders and swatches. Today about 160 entries are still built by hand, and properties have no choices with labels, help, units, steps or dependencies. Property keys stay the same, so layouts keep working (rule 49).
See: Context menus · today and proposed. Plan: Keksuccino/FancyMenu#1863
74Element types bring their own icon
Every element type gets an icon of its own, and New Element, the Layers panel and element pickers show it. Today every type uses the same icon, so the Layers panel can't tell a button from an image.
See: Editor panels, Context menus · today and proposed. Plan: Keksuccino/FancyMenu#1863
75Scripts know what runs them
Whoever opens the script editor tells it who runs the script: a sentence like Runs when Play is clicked, and the $$ names it provides with their definitions, like the Listener Variables of a listener or Checkbox value. Everything the script editor opens gets the same, so $$ suggestions also work in conditions and values. Today the editor only gets the script itself.
See: Script editor · today and proposed. Plan: Keksuccino/FancyMenu#1857
76Texts say what they render
Every text the text editor can open says whether it renders Markdown, formatting codes, plain text or code in a given language, next to one line or multi-line (rule 69), whether placeholders work, a maximum length and a check with a message. String properties and text variables carry the same, so the editor always opens with the right tools. Today it only knows about placeholders and multi-line.
See: Text editor · today and proposed. Plan: Keksuccino/FancyMenu#1864
77Code renders in Noto Sans Mono
FancyMenu's smooth text only has Noto Sans today. The rework adds Noto Sans Mono to the smooth font system as a second font next to it, with the same fallbacks for other languages and emoji, and uses it wherever text is code or has to line up: everything typed in the text editor and its line numbers, inline code and code blocks in Markdown text, and code and identifiers shown in the UI, like $$ names, placeholder IDs, file contents in previews and the values of variables.
See: Text editor · shader code with Find and Replace, Text editor · Text element with the placeholder list, Variables · checking coins
78Material Symbols get updated
FancyMenu bundles Material Symbols Rounded SemiBold 2.904. The rework updates it to the latest version, 2.981 right now, which adds 136 icons. Every icon MaterialIcons has today keeps its name and code point, so nothing that uses one breaks. MaterialIcons gets regenerated from the new font so the new icons get constants too, and the filled style of the same version gets bundled next to it for the few places rule 6 uses it. The mockup already shows 2.981.
See: Script editor · a button’s click script, File browsers · Choose Image, Menu bar · layout editor
79Variables know their units
Number variables get a unit, a step and a display scale, so a volume saved as 0.8 shows as 80% and steps by 5, and a time shows as 3 s or 250 ms. File variables get a media kind, which filters the file browser and brings the preview, like a play button for sounds. Element settings use the same (rule 73).
See: Script editor · today and proposed. Plan: Keksuccino/FancyMenu#1849
80Nothing from a missing mod gets lost
Elements, actions and conditions from a mod that isn't installed stay in the layout exactly as they were saved. They're skipped, saving writes them back unchanged, and they work again once the mod is back. Every registration names its mod and layouts save it next to the identifier, so the script editor can show an Unknown action with a warning that names the mod. Today they're left out while loading, so the next save in the layout editor deletes them for good.
See: Script editor · today and proposed. Plan: Keksuccino/FancyMenu#1857. Bug report: Keksuccino/FancyMenu#1862
81Variables know where they're used
FancyMenu keeps an index of every place that uses a variable name: layouts, universal and disabled ones too, a custom GUI's own settings, global customizations, FancyMenu's settings, listeners, schedulers, and the values and reset values of other variables. It reads the variable definitions, where every variable that takes a variable name has the lookup fancymenu:variables, so actions, conditions, placeholders and element settings from addons count too, plus $$ names in texts and the fmVar uniforms in shader code. It's built in the background when Manage Variables opens and refreshed per changed file. Used in, the Not Used filter, the rename sheet and the delete warning all read it. Text loaded from files, web addresses or HTTP answers can't be indexed, and the window says so.
See: Variables · today and proposed. Variable definitions: Keksuccino/FancyMenu#1849
82Renaming a variable updates every place
Renaming a variable that something uses asks whether to update every place the index knows, other variables' values included. Those places get saved through their normal save path, as one undo step in the window. $$ names only change where the whole name matches, so renaming coins never touches $$coins_record. Text loaded from files, web addresses or HTTP answers, and /fmvariable commands on servers, can't be changed, and the rename sheet warns about that. Only Rename leaves every reference as it is.
See: Variables · today and proposed, Variables · renaming a variable that layouts use
83Variables reset to a value
Next to resetting when the game starts, every variable saves the value it goes back to, so it can reset to 0 or false instead of only to empty. Manage Variables shows it under When the game starts: Keep value or Reset, with the value to reset to and a Reset Now button. Variables from older versions don't have a reset value, so they go back to empty, like today. Only the variables file changes, not layouts.
See: Variables · today and proposed
84Variable changes remember who made them
Setting a variable passes where the change comes from: a script and what runs it (rule 75), an element like a slider or input field, an HTTP request, a server's /fmvariable command, the reset when the game starts, or Manage Variables itself. FancyMenu keeps the last 20 changes per variable in memory for Recent changes in Manage Variables, and repeated changes from the same source become one row with a count. Nothing of it gets saved.
See: Variables · checking coins, Variables · today and proposed
