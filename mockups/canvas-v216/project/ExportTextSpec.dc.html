FancyMenu · UI rework concept · Export as Text

Your setup, as text a helper can read

When something doesn't work, the fastest help comes from showing what you built. Export as Text writes a variable, a listener, a scheduler, a layout or a whole script as short, plain text: every setting and every step, the way the editors show them. It's made for Alice, the support bot on the Discord, and for the people there, so they know the logic on your client without guessing.

What gets in the way today
  • To show what a listener does, you send its file. Every step is a line with one or two long IDs, and the order of the steps stands in yet another line.
  • A condition is spread over three lines that find each other by ID.
  • Actions and conditions show their internal names and raw values, not what the editor shows.
  • Nothing says how things are right now: what a variable holds, whether a scheduler runs, how often a listener ran.
  • The file holds every listener, so a question about one means sending all of them, and its variables and GUIs are in other files.
  • An AI helper can only read so much at once, and most of it goes to IDs.

The window, piece by piece

What the text holds
On the left: the thing you opened it from, then a switch for each kind of thing it uses, with their names. From the Help menu there's a switch for each kind of thing instead.
The text
On the right, read-only, and exactly what gets copied. It changes the moment a switch does. Long lines wrap under their own start, so the levels stay readable.
The footer
How long the text is, then Save as File and Copy. Copy says Copied and the window stays open, so you can save the file too. Nothing in this window changes your setup.

How each kind reads

An action script
{{l.t}}
The first line says what runs it (rule 81). A step is the sentence of its row in the script editor: the action, a colon, then its values with the same words between them.
A layout and its elements
{{l.t}}
An element names its kind, its In-Editor Name, its anchor, place and size. Then come only the settings that differ from a new element of its kind, its conditions and its scripts.
A custom GUI
{{l.t}}
A variable
{{l.t}}
Its value right now. Resets when the game starts is only there when it does.
A scheduler
{{l.t}}
Whether it runs, its timing in the words of the Schedulers window (rule 106), and how often it ran (rule 108).
Several of one kind
{{l.t}}
One thing starts with its kind. Several of one kind stand under one heading, and where they're used is left out. A blank line parts the kinds.

What the text follows

  • It's always English, whatever language the game is in, so every helper can read it.
  • The first line names the versions of FancyMenu, Minecraft and the mod loader.
  • Two spaces deeper is one level deeper: the steps of a block, the settings of an element, the script under its trigger.
  • A condition is the sentence of its chip, like intro_seen is not true. Several are joined with and. A group that needs only one of them is written (… or …).
  • # starts a comment, (off) a step that's turned off, and ! a problem FancyMenu found, like a scheduler nothing starts.
  • Placeholders stand the way they're saved, and $$ names stay names.
  • Folded blocks and folders export all their steps.
  • Left out: internal IDs, icons, colors, what's folded, and settings that still have their default.
  • A line break inside a value is written as \n, so a value never breaks the levels.
  • Something from an addon that isn't installed exports its saved name and values, with a ! line that says so (rule 86).
  • Copy wraps the text in a code block, three backticks before and after, so Discord shows it as typed instead of reading # and _ as formatting. The file has none.
  • Save as File opens the Save browser with a .txt named after the thing, like export-quest-log-key.txt.

Changes beyond the UI

The window above already uses these, so each one is a rework rule.

Export as Text New, rule 155
Everything that holds logic can be exported as plain text that says what it does, to ask Alice or the people on the Discord for help. One window does it for every kind.
Export opens where the thing is New, rule 156
A button in the action bars of the managers and in the script editor, an entry in the Layout menu and in an element's menu, and Export Setup as Text in the Help menu.
The text holds what matters, and nothing else New, rule 157
All settings, every step, the state right now and the problems FancyMenu found. What it uses can be added. IDs and everything only the UI needs stay out.
One way to write each kind New, rule 158
English, the versions first, two spaces a level, and a step is the sentence of its row in the script editor.
Everything writes its own export text New, rule 159
Each kind writes its text in one place. Actions, conditions and elements build it from what they already describe about themselves, so addons export without extra work.
Used In comes from one index Covered, rules 87, 109 and 125
What a script uses and where a thing is used both come from the index the managers already read.
