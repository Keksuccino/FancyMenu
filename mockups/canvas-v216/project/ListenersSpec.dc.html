FancyMenu · UI rework concept · listeners

Listeners you can see working

The Listeners window shows the events every listener listens for, its script in the script editor's own rows, and the Event Variables those events hand over, with their last values updating live. A listener can listen for several events at once, and $$event tells its script which one ran it. Every listener has an icon of its own, picked from every Material icon and emoji FancyMenu ships. Listeners can be turned off, tried with Run Now and switched to other events without rebuilding their script, and Cancel takes every change back. What listeners listen for are called events now, like Keyboard Key Pressed, without the On.

Listener Type
(On Keyboard Key Pressed)

This listener triggers whenever a keyboard key is pressed, which works both while a screen is open and when in-game (in a world/server). The listener keeps firing while the key is held down and the screen continues to receive repeat events.

It provides the following variables for its actions and requirements:

- $$key_name = The resolved display name of the key
- $$key_keycode = The Minecraft key ID (SDL scan code)
- $$key_scancode = The layout-dependent SDL key code
- $$key_modifiers = The active modifier bit mask

What gets in the way
  • A listener listens for exactly one event, so reacting to Server Left and to Singleplayer World Left takes two listeners with the same script, kept in sync by hand.
  • One word means two things: listener is both what you make and what you pick in Choose Listener Type, so it's unclear what a listener's variables belong to.
  • The list only shows names. A listener with a name of its own hides what it listens for, and nothing shows what it does or whether it ever ran.
  • Renaming takes a double-click and editing a right-click, and only two small tips under the description say so.
  • The description repeats the whole help text of the event and shows the script as a bullet list with raw values like last_key:$$key_name and NONE. Comments and folders show up as a red [UNKNOWN BLOCK], and the steps in a folder are left out.
  • Edit Actions and renaming change the running listener right away, and Cancel doesn't take that back, although it warns that it will undo everything.
  • Cancel and the close button always ask, even when nothing changed. Removing a listener warns that it can't be undone, while Cancel brings it back.
  • A listener can't be turned off. Pausing one means deleting it and building its script again later.
  • Choose Listener Type lists all 93 events in the order they were registered, without groups. What they hand over only shows up in their long description, and Copy Variables copies all of them, even when you need one.
  • Picking an event opens the script editor, and the listener only gets added when that script is saved. Cancelling the editor throws the pick away.
  • A script can't be tried without causing its event, like dying or joining a server.
  • Listeners whose event comes from a mod that isn't installed are dropped when FancyMenu starts, so the next save deletes them for good.

The window, piece by piece

The list
Each row shows the listener's own icon, the name and a switch. The second line says what the first one doesn't: the event a named listener listens for, like Keyboard Key Pressed, or what an unnamed one does, like Set Variable, Show Toast. It turns amber for a listener without steps or with an event from a missing mod, with a warning that explains it. Rows of listeners that are off are dimmed. Shift- and Ctrl-click select several, and the search finds names, events and Event Variables, so key_name finds Quest Log Key. Filters show listeners that are off, have problems, ran or haven't run yet, and they sort by name, last run or event.
The icon
The listener's icon sits left of its name in the details, with a small pencil that says it can change. A click opens the icon chooser: a search field, section tabs and one grid with the emoji first and then every Material icon, by popularity. The footer names the icon under the mouse, and Default goes back to the ear. Picking one closes the chooser, the list shows it right away, and Undo takes it back.
Listens for
One row for every event the listener listens for, with its icon and its short description from rule 71, like Happens every time a key is pressed, in menus and while playing. Events that need FancyMenu on the server say so below it (rule 104). Change swaps one event for another and keeps the script, × removes one when there is more than one, and Add Event at the bottom adds another from the same event menu, with the events it has already checked. The list shows a listener with several events as Server Left and 2 more.
Script
The steps in the script editor's own rows and sentences, with tiles, tokens and $$ chips, read-only. A click on a step opens the script editor with that step selected, and a short script shows all of it. After eight rows a button opens the rest in the editor. A script without steps says what doesn't happen yet, like No steps yet, so nothing happens when the weather changes, with Add Steps. The editor shows Runs when a keyboard key is pressed and the Event Variables (rule 81).
Event Variables
Every $$ name the event hands over, what it is, and what it held the last time, updating live with a short highlight. A click on a name copies it with its $$ prefix, Copy All copies all of them, one per line, which replaces Copy Variables to Clipboard. Before the event first happens the values show –, and the note says that Run Now uses the examples. Events like Player Jumped say they hand over nothing. With several events, the names are grouped by where they come from: From every event, with $$event first, then Only from Server Left and so on, which say when they're empty.
Running and testing
The line under the name says how often the listener ran since the game started and when it ran last, or that it's off. Every run draws a ring around its icon in the list, so a listener that runs every second, like one for Variable Updated next to a ticker, is easy to spot. Run Now runs the script once without the event, and a Show Toast in it shows its toast on the screen behind the window. With several events it asks which one to run it as, and F5 runs it as the one that happened last. Test runs don't count as runs.
The footer
Changes apply to the running listeners right away, so you can try them in the game while the window is open, and the note says so (rule 38). Save writes listener_instances.txt. Cancel, the red Close button and Esc put every listener back the way it was when the window opened, and only ask when something changed (rule 68). After a delete, a rename or a change of event, the note says what happened, with Undo.

Special cases it handles

  • A listener whose event comes from a mod that isn't installed shows the event's saved identifier, like questbook:page_turned, and a callout that names the mod. It can't run or be switched on or off, its script stays editable, and Change can point it at an event that's here.
  • Every key press reaches Keyboard Key Pressed, also while typing in this window, so the runs of its listeners go up as you type. That's how the game works today, and the window shows it instead of hiding it.
  • A listener without a name of its own shows as its event, like Server Joined. An empty name in the rename field goes back to that, and the field points out when another listener has the same name.
  • Duplicating names the copy Quest Log Key copy, then Quest Log Key copy 2. Copies run alongside the original.
  • A listener with several events runs its script once every time one of them happens. When two of them happen at the same moment, like Server Left right before Minecraft Closing, it runs twice, and $$event tells the runs apart.
  • When some of a listener's events come from a mod that isn't installed, it keeps listening for the others, and only the missing rows are amber.
  • With several listeners selected, one switch turns all of them on or off. When they disagree its knob sits in the middle, and a click turns them all on (rule 25).
  • Last values belong to the event, since every listener of an event gets the same values. Two listeners for Keyboard Key Pressed show the same values, also when one of them is off.
  • Filters show as a chip under the search field, so a shorter list is never a mystery. The chip's × shows everything again.
  • Listeners keep running while the window is open, so a change can be tried in the game before Save.

Changes beyond the UI

The window above already uses these. They change how listeners and events get saved, run, named or described, so each one is a rework rule.

What listeners listen for are events New, rule 103
A listener is what you make: a name, a switch, a script and the events it listens for. What FancyMenu and addons register, like Keyboard Key Pressed, is an event, and what it hands to the scripts of its listeners are Event Variables. Choose Listener Type turns into the event menu, and the Listener Type of a listener into Listens for. The code follows, with events in their own registry, and saved identifiers stay, so listener files keep loading.
Listeners, schedulers, custom GUIs and variables have icons New, rule 112
Every listener saves an icon: a Material icon or an emoji. New listeners start with the ear, the same icon Manage Listeners has in the menu bar, and old listener files load with it. It replaces the icon of the event's category, which said little once several listeners shared a category.
One icon chooser for icons and emoji New, rule 113
The chooser holds what FancyMenu already ships: the 1,898 emoji of Noto Color Emoji, which its text rendering uses, and the 3,859 icons of its Material icon font. Search goes through the names of both and a few words per icon, like heart for favorite. Recently Used is shared by every chooser.
Listeners can listen for several events New, rule 111
Today a listener has one event in a final field. It gets a list it can change instead, so Change, Add Event and × edit the running listener, and it registers with every event in it. Each event then hands its values over with the run, so names that two events share, like key_name, always come from the event that ran it, the names only other events hand over are empty, and $$event holds the event's identifier, like server_left. Old listener files load as listeners with one event.
Event names drop On New, rule 105
Keyboard Key Pressed instead of On Keyboard Key Pressed. Names that need more get reworded: On Death becomes Player Died, On Jump Player Jumped, On Quit Minecraft Minecraft Closing, On Block Broke Block Broken, On Enter Biome Biome Entered, and On Start Swimming Started Swimming. On Variable Updated [FM Variable] becomes Variable Updated. Only the texts change, so identifiers stay the same.
Listeners can be turned off New, rule 99
Every listener saves whether it's on. Listeners that are off stay in listener_instances.txt and in the window, but don't register with their event, so an event with only off listeners stays inactive and costs nothing. The file gets one extra line for each listener that's off, so old files load with everything on (rule 55).
Listeners count their runs New, rule 100
Each listener counts its runs since the game started and remembers when it ran last, in memory only. Every event already keeps what it handed over last, for the scripts of its listeners, so the window reads the Event Variables from there. Before an event first happens they return defaults like ERROR, so each event also remembers whether it happened yet, and the window shows – until it did.
Scripts run on demand New, rule 101
Run Now runs one listener's script once, with the values its Event Variables hold right now, or with each variable's example (rule 71) when its event hasn't happened yet. It doesn't count as a run, and other listeners of the same event don't run.
Cancel takes everything back New, rule 102
Today the window copies the list, but not the listeners in it, so Edit Actions and renaming change the running listener right away, and Cancel can't undo them. The window works on copies, applies them to the running listeners as you go (rule 38), and puts the originals back on Cancel. Save writes the file.
Events say when they need the server New, rule 104
Structure Entered and Structure Left, their High Precision versions, Entity Spawned, Entity Died and the four raid events only work with FancyMenu on the server. Today a warning line at the top of their description says so. They get a flag instead, so the event menu and the window show it the same way, and the description is only the description.
Listeners with a missing event stay Added to rule 86
A listener whose event isn't registered is dropped when listener_instances.txt loads, and the file gets saved without it at the next change. It stays as saved now, like elements, actions and conditions from a missing mod.
Cancel only asks when something changed Added to rule 68
Manage Listeners asks on Cancel and when its window closes, even when nothing changed, like the script editor. It only asks when there are changes to lose.
Events describe themselves Covered, rule 71
The categories of the event menu, the short descriptions and the description and example of every Event Variable come from the shared descriptions of rule 71. Today the variables only exist inside each event's long description.
The script editor knows the listener Covered, rule 81
Edit Script opens the editor with Runs when a keyboard key is pressed at the bottom and the Event Variables of the listener's event, like on the board Script editor · a listener’s script and its Event Variables. With several events it names all of them, like Runs when the player leaves a server, a singleplayer world closes or Minecraft starts closing, and adds $$event.
