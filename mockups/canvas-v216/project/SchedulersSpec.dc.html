FancyMenu · UI rework concept · schedulers

Schedulers you can watch run

The Schedulers window gives every scheduler a clock with its own icon that fills up until its next run, and a status card with the next run, the runs so far and the time left. Its schedule reads in plain words, Runs, First run and Then every, in ticks, seconds, minutes or hours, right in the details instead of a second window. Start, Stop and Run Now work in the window, Used in lists every place that starts, stops or checks a scheduler, and renaming one updates those places. Changes reach a running scheduler right away, and Cancel takes them back.

What gets in the way
  • The list only shows IDs. Nothing says which schedulers run, how often, when they run next or whether one already finished.
  • The timing sits in a second window behind Edit Settings, in milliseconds only, so ten minutes is 600000.
  • Tick Delay and Ticks to Run count runs of the script, not game ticks, and a Tick Delay of 0 secretly means every 50 ms.
  • The status is Running or Not Running. A scheduler that finished looks like one that never ran.
  • Changed settings don't reach a running scheduler until it's started again, and nothing says so.
  • Renaming stops a running scheduler, and Start Scheduler actions with the old ID silently stop working.
  • Add Scheduler opens the script editor first, and the scheduler only gets added when that script is saved, with an ID like scheduler_3f2a9c1e-… that nobody remembers.
  • Nothing shows where a scheduler gets started, stopped or checked, or warns that nothing starts one at all.
  • Start Now and Stop Now both say that a scheduler can't be started again until it finishes.
  • Everything applies right away and there's no Cancel, while Remove Scheduler warns that it can't be undone.
  • A script can't be tried without starting the scheduler and waiting for its first run.
  • A wrong number or ID only shows up as a dialog after Done in the settings window.

The window, piece by piece

The list
Every row has a clock: the scheduler's own icon, and a ring that fills until the next run. Each run draws a short ring around it. A dashed ring is the wait before the first run, and schedulers that run more than once a second breathe instead. The second line is the schedule in a few words, like Every 6 s or Once, after 10 min, and turns amber for a scheduler without steps or one that nothing starts. The button on the right starts and stops it. The search finds names and what the scripts do, so audio finds every scheduler that plays something. Filters show the ones that run, don't run, start with the game or have problems, sorted by name, next run or last run.
The status card
Shows while the scheduler runs: Next run in 3 s, and how often it ran since it started, or Run 4 of 10 · done in 7 s for one with a set number of runs. The bar fills until the next run, so its speed is the schedule. A countdown of up to 40 runs gets one block per run instead, each filling until its run happens. Before the first run it says First run in 8 s over a lighter bar, and fast ones say Runs every tick, 20 times a second. The icon left of the name opens the icon chooser, and Default goes back to the timer. The line under the name says when and how it started, like Running since 12:21:03, with the game, or how it ended: Stopped at 12:39:10 after 14 runs, or Finished at 12:31:03 after its only run.
Schedule
Starts with the game replaces Start on Launch, and says that it also starts after FancyMenu reloads. Runs is Until stopped, Once or Several times, with how many. First run is Right away or After a wait, with how long, and Then every is gone for Once. Durations have a unit menu with Ticks, Milliseconds, Seconds, Minutes and Hours. A pick keeps the number, so 6 s becomes 6 min, and ↑ ↓ step it, Shift by 10. Under one tick, Then every says in amber that runs pile up in every tick. Every change applies right away, also while it runs, and the footer says when the next run is now.
Script
The steps in the script editor's own rows and sentences, read-only, like in Listeners. A click on a step opens the script editor with that step selected. Run Now and F5 run the script once, without starting the scheduler, so a Reset Element Animator replays the fireflies behind the window and a Show Toast shows its toast. A script without steps says that nothing happens when it runs, with Add Steps.
Used in
Every place that uses the name, grouped by layout, custom GUI, listener and other schedulers like in the Variables window: Start Scheduler and Stop Scheduler in scripts, and Scheduler Is Running in conditions, each with a button that opens it there. A scheduler that doesn't start with the game and that no script starts gets a callout: Nothing starts rain_ambience, with what only checks it and Start With the Game right there.
The footer
Changes apply to the schedulers right away, also to running ones, and the note says so (rule 38). Save writes scheduler_instances.txt. Cancel, the red Close button and Esc put every scheduler back the way it was when the window opened, and only ask when something changed (rule 68). Starting and stopping aren't changes, so Cancel leaves them, and its sheet says so. After a change the note says what happened, with Undo.

New, start, rename

New Scheduler
1New Scheduler or Ctrl+N adds new_scheduler, every second until stopped, and selects its name.
2Typing names it. Spaces turn into _ and capitals into small letters, and a name that's taken turns the field red.
3Add Steps opens its script in the script editor.
4Start tries it, and Starts with the game makes it start with every launch.
Start, stop, try
1Start, the row's button or Space start it. Without a wait, the first run is right away.
2The clock and the status card count down to the next run, and every run draws a ring around the tile.
3Stop stops it. One with a set number of runs stops by itself, and the line under its name says when it finished.
4Run Now runs the script once and leaves the schedule as it is.
Rename
1F2 or the pencil, a new name, and Enter.
2When something uses the name, a sheet offers Rename and Update 3 Places, Only Rename or Cancel.
3A running scheduler keeps running under its new name.
4Undo, Ctrl+Z or Cancel take the name and the updated places back.

Special cases it handles

  • Start Scheduler does nothing for a scheduler that runs already, so pressing Play twice doesn't restart its countdown. Stop, then Start, restarts it.
  • Deleting a running scheduler stops it, and Delete only asks when the name is still used somewhere. Undo brings it back and starts it again.
  • A change that leaves fewer runs than it already did, like Once after 7 runs, finishes it. Undo lets it go on from there.
  • Intervals under one tick work like today: several runs pile up in every tick, and Then every says so in amber. When the game lags, runs can pile up in one tick too, because the timer runs beside the game.
  • Duplicating names the copy fireflies_copy, then fireflies_copy_2. Copies don't run, and nothing uses them yet.
  • Switching profiles or reloading FancyMenu stops every scheduler and starts the ones that start with the game again, so their runs count from zero.
  • Schedulers run in every menu and while playing, also with the window closed. The window shows what they did since the game started.
  • With several selected, one button starts or stops all of them, and Start rain_ambience or Start the Other 2 starts the ones that don't run. Starts with the game shows its knob in the middle when they disagree (rule 25).
  • Filters show as a chip under the search field, so a shorter list is never a mystery. The chip's × shows everything again.
  • A duration that isn't a number above 0 turns its field red and says what it needs, like Type how long it waits between runs, like 6. The scheduler keeps the last good value until then.

Changes beyond the UI

The window above already uses these. They change how schedulers get saved, run, named or found, so each one is a rework rule.

Scheduler timing speaks plainly New, rule 106
Start Delay, Tick Delay, Ticks to Run and Start on Launch become First run, Then every, Runs and Starts with the game, in every language file. scheduler_instances.txt keeps saving milliseconds. A Then every of 0 loads as one tick, 50 ms, which is what it means today, and gets saved as 50 (rule 55). The unit only changes how the window shows it.
Running schedulers take changes right away New, rule 107
startScheduler reads the delays once, so a running scheduler keeps its old timing until it starts again. It reads them for every run instead: the next run comes one new interval after the last one, or right away when that's past, and the runs so far count toward a new Several times. Renaming moves the run state to the new name, so it keeps running. Today both ways of renaming stop it, because stopScheduler only finds it under the old name.
Schedulers report how they run New, rule 108
Every run state keeps when it started, what started it (the game, the Schedulers window or a script), how many runs it did and when the next one is due. A scheduler that finished remembers that and when, so it doesn't look like one that never ran. In memory only, for the window, like the runs of listeners (rule 100).
Schedulers know where they're used New, rule 109
The index of rule 87 also collects scheduler names: every variable whose definition has the lookup fancymenu:schedulers, like the values of Start Scheduler, Stop Scheduler and Scheduler Is Running, also from addons. Used in, the With Problems filter, the rename sheet and the delete warning read it, and renaming updates those places the way rule 88 does for variables.
New schedulers get a name to type over New, rule 110
New Scheduler adds new_scheduler, then new_scheduler_2, instead of scheduler_ and a UUID. It's added right away without steps, instead of once its script was saved in the script editor, and it runs every second until stopped, instead of every tick.
Listeners, schedulers, custom GUIs and variables have icons New, rule 112
Every scheduler saves an icon, a Material icon or an emoji, in one more line of scheduler_instances.txt. New ones start with the timer, the icon of Manage Schedulers in the menu bar, and old files load with it.
One icon chooser New, rule 113
The same chooser as in Listeners, Custom GUIs and Variables, with every emoji of the bundled Noto Color Emoji and every icon of the bundled Material icon font, and a Recently Used row all four windows share.
Scripts run on demand Added to rule 101
Run Now in the Schedulers window runs the scheduler's script once, without starting it, counting a run or moving its next run.
Cancel takes back every change Added to rule 102
Manage Schedulers applies every change to the running schedulers and the file right away, and has no Cancel. It works like Manage Listeners now: on copies, applied as you go, with the originals back on Cancel. Save writes scheduler_instances.txt. Starting and stopping aren't changes, so Cancel leaves them as they are.
The script editor knows the scheduler Covered, rule 81
Edit Script opens the editor with Runs every 6 seconds while fireflies runs at the bottom, so the script says where it belongs.
