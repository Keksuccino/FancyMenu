FancyMenu · UI rework concept · rules, continued

Fix during the rework

Bugs we found while making these mockups, and changes that come with the rework. The numbers continue from the rules on the board above.

60Line-break markers stay out of saved text
One-line values save line breaks as %!n!% and the spaces after them as %!s!%. Those markers end up in saved layouts, value previews and copied text, and every place that uses such a value has to strip them again.
See: Text editor · today and proposed. Fixed by rule 75: Keksuccino/FancyMenu#1860
61Toast titles without markers
A line break typed into the title of a Show Toast action leaves %!n!% in the toast, because the title never gets the markers removed.
See: Text editor · today and proposed. Fixed by rule 75: Keksuccino/FancyMenu#1860
62HTTP bodies keep their line breaks
The body of a Send HTTP Request action is saved as a one-line value, so its line breaks get deleted: a JSON body loses all its formatting, and "a", a new line and "b" get sent as "ab".
See: Text editor · today and proposed. Fixed by rule 75: Keksuccino/FancyMenu#1860
63Write File can write \n
Write File saves line breaks as the text \n and turns them back into line breaks when it runs, so it can't write an actual backslash followed by n.
See: Text editor · today and proposed. Fixed by rule 75: Keksuccino/FancyMenu#1860
64Dragging scrolls up too
While dragging an entry in the action script editor, moving above the list never scrolls it up, because the check compares the pointer’s x position with the list’s top y position. Dragging close to the left edge of the window scrolls up instead, anywhere in the list.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1852
65Folders and comments move like other steps
Move Up and Move Down, and Shift+↑/↓, do nothing for folders and comments in the action script editor. The menu entries are active, but the entry stays where it is.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1853
66A While runs again after a timeout
A While loop that hits its 3 second timeout once is skipped on every later run until FancyMenu reloads, because its timeout flag is only reset by a run that finishes in time. A timeout only stops the run that hit it.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1854
67Added and dropped steps land in the same place
Adding a step to a selected block puts it at the end of the block, while dropping one on the block puts it at the start. Both put it right below the block header.
See: Script editor · today and proposed. Bug report: Keksuccino/FancyMenu#1855
68Cancel only asks when something changed
The action script editor and Manage Listeners ask whether to discard everything on Cancel and when their window closes, even when nothing changed. They only ask when there are changes to lose. Pre-Load Resources and Manage Custom GUIs, which never ask today, ask the same way.
See: Script editor · today and proposed, Listeners · today and proposed, Pre-Load Resources · today and proposed, Custom GUIs · today and proposed. Bug report: Keksuccino/FancyMenu#1856
69Requirements become Conditions
Everything the UI calls a requirement is called a condition, all over FancyMenu: Loading Requirements becomes Loading Conditions, Manage Requirements becomes Manage Conditions, requirement groups become condition groups, and Requirement Caching becomes Condition Caching. The condition editor goes along, so texts like Edit Requirement Value, This requirement has no value and You need to edit the requirement value first! talk about the condition and its variables instead (rule 72). That's about 140 texts in en_us.json, plus the same ones in every other language file. The conditions themselves keep their names, like Is Singleplayer. Saved identifiers keep "requirement", so old layouts keep loading. Class names and the API can be renamed along with it, since addons are allowed to break (rule 55).
See: Script editor · today and proposed, where If and While already talk about conditions
70Action variables get types
Every action takes one string today, so many of them pack several settings into one text, like intro_seen:true for Set Variable or url|||POST|||{…} for Send HTTP Request. Each action can split it into variables, each with a type from the same enum as placeholder variables, plus a sentence for its row in the script editor (rule 71). Set Variable gets Variable and New value, Play Audio gets Sound, Volume and Channel. The editor then shows the right control for every variable, the same way as for placeholders. Actions that don't declare variables keep one text variable with the raw value, and saved values stay as they are.
See: Script editor · today and proposed. Variable types: Keksuccino/FancyMenu#1849
71Everything describes and registers itself the same way
Placeholders, actions, conditions and events all get a display name, a description and a category from one shared list, plus a display name, description, type, default and example for every variable. Event Variables get all of that except a display name, because people type them as $$key_name and the UI shows exactly that. Their texts are plain localized strings found by a key convention, instead of Components with formatting codes, so the UI can search, sort and style them itself. All four share one registry base with the same registration rules, and the same job gets the same method name in every kind, like one method for whether an entry shows in the editor. Actions and conditions also get a row sentence with a slot for each variable, like Set Variable {variable} to {value} or {variable} is {value}, so the script editor shows every step in words in every language, in whatever word order the language needs, with the slots as tokens. Conditions get a second sentence for Is Not, like {variable} is [not] {value}, where the brackets mark the words to highlight. Variables left out of the sentence only show in the form. A step without a sentence shows its name followed by its variables, and registration warns about slots that aren't variables.
Full plan: Keksuccino/FancyMenu#1857
72Values become variables
What placeholders, actions and conditions take as input is called a variable, not a value, everywhere. In the editors, Edit Action Value, Configure Value, Value: and This action has no value talk about variables, and the same goes for conditions. Descriptions too, like the Required values:, Optional values: and Values: lists of placeholders, or Takes the key of an effect as value. Every language file follows. In the API, getValueNames, hasValue, hasRawValue, getValueDisplayName, getValuePreset, getValueFormattingRules and editValue make way for the variable definitions, and the values map of DeserializedPlaceholderString becomes the shared variables object. The placeholder string writes "vars" instead of "values" and still reads "values", so old layouts keep working. What events hand to the scripts of their listeners are Event Variables (rule 103). A variable still has a value, so phrases like the value of a variable, or names like Is Variable Value and Possible Values: 0-100, stay.
See: Text editor, Script editor · today and proposed. Plans: Keksuccino/FancyMenu#1849, Keksuccino/FancyMenu#1857
73One clean system for $$ names
$$name reads something by its name: an Event Variable like $$old_value, a FancyMenu variable like $$coins, or $$value, the current value of a Checkbox or Slider. That last one isn't a variable, so these are element values, and the UI names them after their element, like Checkbox value. In the code, ValuePlaceholderHolder, addValuePlaceholder, getValuePlaceholders, applyValuePlaceholders and the two separate "$$" constants drop the placeholder name and become one shared resolver for $$ names. Events and elements hand their names to the context a script or condition runs in, instead of copying them into every action, block and condition like today. Texts stop calling them placeholders, like the '$$value' placeholder in the Checkbox and Slider descriptions. At every $$ the longest matching name wins, so $$item_key never eats the start of $$item_key_count, and $$ works in every text, also in ones without a placeholder. Both go wrong today.
See: Script editor · today and proposed. Plan: Keksuccino/FancyMenu#1857. Bug reports: Keksuccino/FancyMenu#1858, Keksuccino/FancyMenu#1859
74New variables can't take $$ names
Wherever someone names a new FancyMenu variable, like Manage Variables, Set Variable, the linked variable of Checkbox, Slider and Input Field, or the response variable of Send HTTP Request, names that Event Variables or element values use, like old_value, player_name or value, are refused, and the field says what uses the name. Old layouts, /fmvariable from a server and addons that add new events can still bring such a variable, so it keeps working: Get Variable reads it by name, Manage Variables marks it, and when both have the same name, $$ always picks the Event Variable or element value, so $$old_value in a listener script always means the event's variable.
Plan: Keksuccino/FancyMenu#1857
75Typed line breaks are stored one way
Every text property says whether it's one line or multi-line and holds real line breaks, and only the layout file escapes them, in one place. One-line values keep the line breaks and indentation people type, and FancyMenu joins them in one single place when the value gets used, instead of %!n!% and %!s!%. %n% and a typed \n stay text codes, because variables, placeholders and server data use them to make line breaks. Old layouts convert per property, the way each one uses its markers today, so the same text comes out. The Toast title and message, the Write File content and the HTTP body become multi-line, and old HTTP bodies keep sending as one line. This fixes rules 60 to 63.
See: Text editor · today and proposed. Plan: Keksuccino/FancyMenu#1860
76Steps can be turned off
Every step in the script editor gets a Runs switch, and Ctrl+/ turns the selected steps on or off. A step that's off stays where it is, dimmed with an Off chip, and the script skips it, like commented-out code. Turning off a block, like If, While, Folder or Delay, skips everything inside it. Turning off an If also skips its Else If and Else, while turning off a single Else If or Else only skips that branch. The layout saves one extra line for each step that's off, so old layouts load with everything on (rule 55).
See: Script editor · today and proposed
77Collapsing is view state
Collapsing a block in the script editor isn't an edit. It's still saved with the layout, so a script opens the way it was left, but Undo and Redo skip it, and it doesn't count as a change, so Cancel doesn't ask about it (rule 68). Every branch collapses on its own: collapsing an If only hides the If's own steps, and Else If and Else get their own collapse arrow and saved flag. In old layouts, a collapsed If opens collapsed, and its Else If and Else open expanded.
See: Script editor · today and proposed
78Variable actions get shorter names
The display names of Set Variable Value (FM Variable), Delete Variable (FM Variable), Clear All Variables (FM Variable) and the Is Variable Value (FM Variable) condition become Set Variable, Delete Variable, Clear All Variables and Is Variable Value in every language file, matching Get Variable (rule 57). Their identifiers stay the same, so layouts keep working.
See: Script editor · today and proposed
79Element settings describe themselves
Every element setting, the shared ones included, becomes a property that knows its value, default, type, choices, range, unit, step, help, section and the setting it depends on. Context menus build their rows from that alone, which is what rules 17, 18, 20, 25 and 26 need: the value on the row, the reset arrow, Mixed, switches, sliders and swatches. Today about 160 entries are still built by hand, and properties have no choices with labels, help, units, steps or dependencies. Property keys stay the same, so layouts keep working (rule 55).
See: Context menus · today and proposed. Plan: Keksuccino/FancyMenu#1863
80Element types bring their own icon
Every element type gets an icon of its own, and New Element, the Layers panel and element pickers show it. Today every type uses the same icon, so the Layers panel can't tell a button from an image.
See: Layout editor · a button selected, Context menus · today and proposed. Plan: Keksuccino/FancyMenu#1863
81Scripts know what runs them
Whoever opens the script editor tells it who runs the script: a sentence like Runs when Play is clicked, and the $$ names it provides with their definitions, like the Event Variables of a listener's event or Checkbox value. Everything the script editor opens gets the same, so $$ suggestions also work in conditions and values. Today the editor only gets the script itself.
See: Script editor · today and proposed. Plan: Keksuccino/FancyMenu#1857
82Texts say what they render
Every text the text editor can open says whether it renders Markdown, formatting codes, plain text or code in a given language, next to one line or multi-line (rule 75), whether placeholders work, a maximum length and a check with a message. String properties and text variables carry the same, so the editor always opens with the right tools. Today it only knows about placeholders and multi-line.
See: Text editor · today and proposed. Plan: Keksuccino/FancyMenu#1864
83Code renders in Noto Sans Mono
FancyMenu's smooth text only has Noto Sans today. The rework adds Noto Sans Mono to the smooth font system as a second font next to it, with the same fallbacks for other languages and emoji, and uses it wherever text is code or has to line up: everything typed in the text editor and its line numbers, inline code and code blocks in Markdown text, and code and identifiers shown in the UI, like $$ names, placeholder IDs, file contents in previews and the values of variables.
See: Text editor · shader code with Find and Replace, Text editor · Text element with the placeholder list, Variables · checking coins
84Material Symbols get updated
FancyMenu bundles Material Symbols Rounded SemiBold 2.904. The rework updates it to the latest version, 2.981 right now, which adds 136 icons. Every icon MaterialIcons has today keeps its name and code point, so nothing that uses one breaks. MaterialIcons gets regenerated from the new font so the new icons get constants too, and the filled style of the same version gets bundled next to it for the few places rule 6 uses it. The mockup already shows 2.981.
See: Script editor · a button’s click script, File browsers · Choose Image, Menu bar · layout editor
85Variables know their units
Number variables get a unit, a step and a display scale, so a volume saved as 0.8 shows as 80% and steps by 5, and a time shows as 3 s or 250 ms. File variables get a media kind, which filters the file browser and brings the preview, like a play button for sounds. Element settings use the same (rule 79).
See: Script editor · today and proposed. Plan: Keksuccino/FancyMenu#1849
86Nothing from a missing mod gets lost
Elements, actions and conditions from a mod that isn't installed stay in the layout exactly as they were saved, and listeners whose event comes from such a mod stay in listener_instances.txt. They're skipped, saving writes them back unchanged, and they work again once the mod is back. Every registration names its mod, and layouts and listener_instances.txt save it next to the identifier, so the script editor can show an Unknown action and Manage Listeners an unknown event, each with a warning that names the mod. Today they're left out while loading, so the next save in the layout editor, or the next change in Manage Listeners, deletes them for good.
See: Script editor · today and proposed, Listeners · an event from a mod that isn’t installed. Plan: Keksuccino/FancyMenu#1857. Bug report: Keksuccino/FancyMenu#1862
87Variables know where they're used
FancyMenu keeps an index of every place that uses a variable name: layouts, universal and disabled ones too, a custom GUI's own settings, global customizations, FancyMenu's settings, listeners, schedulers, and the values and reset values of other variables. It reads the variable definitions, where every variable that takes a variable name has the lookup fancymenu:variables, so actions, conditions, placeholders and element settings from addons count too, plus $$ names in texts and the fmVar uniforms in shader code. It's built in the background when Manage Variables opens and refreshed per changed file. Used in, the Not Used filter, the rename sheet and the delete warning all read it. Text loaded from files, web addresses or HTTP answers can't be indexed, and the window says so.
See: Variables · today and proposed. Variable definitions: Keksuccino/FancyMenu#1849
88Renaming a variable updates every place
Renaming a variable that something uses asks whether to update every place the index knows, other variables' values included. Those places get saved through their normal save path, as one undo step in the window. $$ names only change where the whole name matches, so renaming coins never touches $$coins_record. Text loaded from files, web addresses or HTTP answers, and /fmvariable commands on servers, can't be changed, and the rename sheet warns about that. Only Rename leaves every reference as it is.
See: Variables · today and proposed, Variables · renaming a variable that layouts use
89Variables reset to a value
Next to resetting when the game starts, every variable saves the value it goes back to, so it can reset to 0 or false instead of only to empty. Manage Variables shows it under When the game starts: Keep value or Reset, with the value to reset to and a Reset Now button. Variables from older versions don't have a reset value, so they go back to empty, like today. Only the variables file changes, not layouts.
See: Variables · today and proposed
90Variable changes remember who made them
Setting a variable passes where the change comes from: a script and what runs it (rule 81), an element like a slider or input field, an HTTP request, a server's /fmvariable command, the reset when the game starts, or Manage Variables itself. FancyMenu keeps the last 20 changes per variable in memory for Recent changes in Manage Variables, and repeated changes from the same source become one row with a count. Nothing of it gets saved.
See: Variables · checking coins, Variables · today and proposed
91Every change marks the layout as changed
Ctrl+V pastes without an undo step and without marking the layout unsaved, while Paste in a menu does both. Move One Layer Up and Down (in the element menu and in Layers), moving groups, renaming a layer and changing the layout-wide loading requirements skip both as well, so closing the editor doesn't even warn about them.
See: Layout editor · today and proposed
92Element Animators become layout animations
Element Animator elements turn into layout animations when a layout loads (rule 55): their keyframes become Position and Size tracks for each target, timing offsets shift each target's keyframes, and offset mode becomes Move From Resting Position. animated_offset_x and animated_offset_y, which only exist while an animation runs, stop being written into layout files.
See: Layout editor · editing a keyframe
93Animations move smoothly
Animated values interpolate linearly and get rounded to whole GUI pixels, so motion visibly steps at high GUI scales (#1216), and an element jumps when two keyframes use different anchors, because a whole segment takes the anchor of its end. Values interpolate in fractions with each keyframe's easing, and the anchor never changes in the middle of a segment.
See: Layout editor · editing a keyframe
94Hidden vanilla widgets say hidden
Element › Deleted Vanilla Widgets lists widgets that are only hidden, never deleted. They show up in Layers with a crossed-out eye that shows them again, and every text calls them hidden.

Shortcut labels in menus and tooltips always say Ctrl, even on macOS, where the shortcuts use Cmd.

In Layers, dragging only starts on a row that is already selected, and rows only get selected when the mouse button is released, so moving a layer takes two presses.

98Every saved setting gets a row
Some saved settings have no UI at all, like the header and footer shadows and the tooltip's interactable flag, and the Markdown colors of texts are plain text inputs instead of colors. Each gets its row in the Inspector with the control that fits it.

99Listeners can be turned off
Every listener saves whether it's on, and the Listeners window gives each one a switch. Listeners that are off stay in listener_instances.txt and in the window, but don't register with their events, so an event with only listeners that are off stays inactive and costs nothing. The file gets one extra line for each listener that's off, so old files load with everything on (rule 55).
See: Listeners · today and proposed
100Listeners count their runs
Each listener counts its runs since the game started and remembers when it ran last, in memory only, for the Listeners window. Every event already keeps what it handed over last, for the scripts of its listeners, so the window reads the Event Variables from there. Before an event first happens they return defaults like ERROR, so each event also remembers whether it happened yet, and the window shows – until it did.
See: Listeners · the quest log key, running live
101Listener and scheduler scripts run on demand
Run Now in the Listeners window runs one listener's script once, with the values its Event Variables hold right now, or with each variable's example (rule 71) when its event hasn't happened yet. It doesn't count as a run, and other listeners of the same event don't run. For a listener with several events it asks which one to run it as (rule 111). Run Now in the Schedulers window runs a scheduler's script once the same way, without starting it, counting a run or moving its next run.
See: Listeners · today and proposed, Schedulers · today and proposed
102Cancel takes back every listener and scheduler change
Manage Listeners copies the list of listeners, but not the listeners in it, so Edit Actions and renaming change the running listener right away, and Cancel can't undo them, although its warning says it undoes everything. The window works on copies, applies them to the running listeners as you go (rule 38), and puts the originals back on Cancel. Save writes the file. Manage Schedulers has no Cancel at all and applies every change to the running schedulers and to scheduler_instances.txt right away. It works the same way now, and starting or stopping a scheduler isn't a change, so Cancel leaves it.
See: Listeners · today and proposed, Schedulers · today and proposed
103What listeners listen for are events
A listener is what you make in Manage Listeners: a name, an on/off switch, a script and the events it listens for (rule 111). What FancyMenu and addons register, like Keyboard Key Pressed or Server Joined, is an event, all over FancyMenu: Choose Listener Type becomes the event menu of New Listener, the Listener Type of a listener becomes the event it listens for, and the variables an event hands to the scripts of its listeners are Event Variables instead of Listener Variables. Texts in every language file follow, like event descriptions that start with This listener triggers. In the code, AbstractListener becomes the base class of events with its own EventRegistry, CustomVariable becomes the event's variable definition, and ListenerInstance stays the listener. Addons register events instead of listeners, which is fine, because addons are allowed to break (rule 55). Saved identifiers stay the same, like listener_provider_identifier and the identifier of every event, so listener_instances.txt keeps loading.
See: Listeners · today and proposed, Script editor · a listener’s script and its Event Variables
104Events say when they need the server
Structure Entered and Structure Left, their High Precision versions, Entity Spawned, Entity Died and the four raid events only work with FancyMenu on the server, and today a warning line at the top of their description says so. They get a flag instead, so the event menu and the Listeners window show it the same way, and the description is only the description.
See: Listeners · adding a listener
105Event names drop On
Event names say what happened, without On in front: On Keyboard Key Pressed becomes Keyboard Key Pressed, and On Server Joined becomes Server Joined. Names that need more than that get reworded: On Death becomes Player Died, On Jump Player Jumped, On Quit Minecraft Minecraft Closing, On Block Broke and On Item Broke Block Broken and Item Broken, On Enter Biome Biome Entered, the same for structures and raid areas, and On Start Swimming and the other Start and Stop names Started Swimming and so on. On Variable Updated [FM Variable] becomes Variable Updated, like the variable actions of rule 78. Only the texts change, in every language file, so identifiers stay the same.
See: Listeners · adding a listener
106Scheduler timing speaks plainly
Start Delay, Tick Delay, Ticks to Run and Start on Launch become First run, Then every, Runs and Starts with the game, in every language file, and the Schedulers window shows durations in ticks, ms, s, min or h. A tick there meant a run of the script, so the word goes away. scheduler_instances.txt keeps saving milliseconds. A Then every of 0 loads as one tick, 50 ms, which is what it means today, and gets saved as 50 (rule 55).
See: Schedulers · today and proposed
107Running schedulers take changes right away
startScheduler reads the delays and the number of runs once, so a running scheduler keeps its old timing until it's started again. It reads them for every run instead: the next run comes one new interval after the last one, or right away when that's already past, and the runs so far count toward a new number of runs. Renaming moves the run state to the new name, so the scheduler keeps running. Today both ways of renaming stop it, because stopScheduler only finds it under the old name.
See: Schedulers · fireflies, running live
108Schedulers report how they run
Every run state keeps when it started, what started it (the game, the Schedulers window, or a script and where that script is), how many runs it did and when the next one is due. A scheduler that finished remembers that it finished and when, so the window can tell it apart from one that never ran. In memory only, like the runs of listeners (rule 100).
See: Schedulers · a countdown, run 4 of 10
109Schedulers know where they're used
The index of rule 87 also collects scheduler names: every variable whose definition has the lookup fancymenu:schedulers, like the values of Start Scheduler, Stop Scheduler and Scheduler Is Running, also from addons. Used in, the With Problems filter, the rename sheet and the delete warning of the Schedulers window read it, and renaming a scheduler updates those places the way rule 88 does for variables.
See: Schedulers · renaming one that a layout uses, Schedulers · one that nothing starts
110New schedulers get a name to type over
New Scheduler adds new_scheduler, then new_scheduler_2, instead of scheduler_ and a UUID. It's added right away without steps, instead of once its script was saved in the script editor, and it runs every second until stopped instead of every tick.
See: Schedulers · adding a scheduler
111Listeners can listen for several events
A listener keeps a list of events instead of one: the final parent of ListenerInstance becomes a list it can change, so Change, Add Event and × edit the running listener in place, and it registers with every event in the list. listener_instances.txt saves them in listener_provider_identifiers, comma-separated, and reads the listener_provider_identifier of old files as a list of one (rule 55). Each event runs the script once when it happens. Event Variables stop being placeholders that the event adds to the script once: an event hands its values over with each run, so names that several events share, like key_name, always hold the values of the event that ran the script, names that only its other events hand over are empty, and $$event holds the identifier of the event, like server_left, whenever a listener has more than one. A listener whose events come partly from a missing mod keeps running for the others (rule 86).
See: Listeners · one listener, three events, Listeners · adding an event to a listener
112Listeners, schedulers, custom GUIs and variables have icons
Every listener, scheduler, custom GUI and variable saves an icon: the name of a Material icon or an emoji, picked in the icon chooser (rule 113). It shows in their lists, in the details and wherever they're listed. New ones start with a default: the ear for listeners, the timer for schedulers and the $ for variables, the icons their windows have in the menu bar. Manage Variables gets the $ there too, instead of the code icon. A custom GUI's default says what it is: the screen icon, or the popup icon while Popup is on. It replaces the icon of a listener's event category and of a scheduler's first action, which looked alike for many of them. listener_instances.txt, scheduler_instances.txt, custom_gui_screens.txt and user_variables.db save it in one more line, as material:<name> or emoji:<code points>, and old files load with the default (rule 55).
See: Listeners · choosing an icon, Schedulers · searching for an icon, Custom GUIs · choosing an icon for a popup, Variables · searching for an icon
113One icon chooser for icons and emoji
Everything that lets you pick an icon opens the same chooser, built like an emoji picker: a search field, a tab for each section, one grid and a footer. The grid holds what FancyMenu ships: first the 1,898 emoji of the bundled Noto Color Emoji, in the Unicode order without skin tones, then the 3,859 icons of MaterialIcons in six groups, by popularity. Search finds emoji names, icon names and a few words per icon, like heart for favorite, and the arrow keys and Enter pick from the results. The footer names the icon under the mouse, and Default goes back to the default icon. Recently Used is shared by every chooser and saved in FancyMenu's options. Only the rows in view are drawn, and the emoji render with the color emoji support the text renderer already has. It is built as one reusable component, so other parts of the UI can use it later, and each place that opens it can turn off the Material icons to offer emoji only.
See: Icon chooser component, Listeners · choosing an icon
114The AFMA Creator checks frames before it starts
When frames are added, AfmaCreatorState reads every PNG's size from its header, the first 24 bytes, without decoding it, and the numbers in the file names. Frames of another size, an intro that doesn't match the main frames and gaps in the numbering show on the frame rows right away, localized, and Create AFMA stays off until every frame fits. The folders get checked again when the game gets the focus back, so a frame fixed in another program shows as fixed. Today a frame of another size only throws an IOException with its full path halfway through the export, and the error texts of AfmaCreatorState are English only.
See: AFMA Creator · frames that don't fit
115The AFMA Creator previews frames
A background thread decodes the frames into small copies at the preview's size and keeps them in a cache. The preview plays them with the window's speed, intro and loops, the way AfmaTexture plays the finished file, and stops on the last frame after the last loop like it does. The thumbnails of the frame rows and of the timeline come from the same copies, so hundreds of 4K frames scrub smoothly and the window never waits for a frame.
See: AFMA Creator · ready to create
116The AFMA Creator is a window that remembers
AfmaCreatorScreen becomes a window body like the other tools, so the menu bar and the screen behind it stay usable while it works. The export keeps running while the window is collapsed, and closing the window during an export asks first instead of stopping it. The last frames, speed, loops, quality and file name are saved in FancyMenu's options and come back the next time it opens. Dropped files go to the frame row under the pointer (rule 118).
See: AFMA Creator · closing while it creates
117The encoder reports progress and results as data
AfmaEncodeProgress carries English texts today, like Analyzing AFMA frames for export... and details like main frame 12/240. It reports the phase, the part and the frame number instead, and the job keeps when it started, so the window can say Analyzing main frame 20 of 72 in every language, show that frame in the preview and estimate the time left. A finished job also returns the file's size and how many frames it stores in full, from AfmaEncodePlan.countFrames, for the result card.
See: AFMA Creator · creating, AFMA Creator · created
118Dropped files land where the pointer is
GLFW, the window library Minecraft uses, only reports files once they're dropped. There's no event while files get dragged over the window, so nothing in FancyMenu can light up a drop target, show where files will go or say which ones get skipped before the drop. Every place that takes files says so up front instead, with a hint like Drop files here to copy them into this folder, and decides by where the pointer is when the drop arrives, read with glfwGetCursorPos. Right after a drop it shows what happened: copied files are tagged New and selected, an import starts its progress sheet, and a note says where files went and which ones got skipped, with Undo. A file that can't be used gets a short alert with the error beep instead of being dropped silently.

119Pre-loading never freezes the game start
ResourcePreLoader.preLoadAll runs in FancyMenu's reload listener on the main thread and waits up to 120 seconds for each resource, one after the other, so the loading screen freezes while a slow download runs. Pre-loading becomes its own reload step that starts every resource at once and gives Minecraft a future that completes when all of them are done, or after 30 seconds in all, so the loading screen keeps drawing.

AudioElement.buildShuffleIndexesList builds a pool with every track in it as often as its weight says, then turns the pool into a list of unique tracks, and the next track gets picked from that list. 158One way to write each kind
The text is English in every game language and starts with the versions of FancyMenu, Minecraft and the mod loader. A step is the sentence of its row in the script editor: the action, a colon, then its values with the same words between them. A condition is the sentence of its chip. Two spaces deeper is one level deeper, # starts a comment, (off) a step that's turned off and ! a problem. Placeholders stand the way they're saved. Copy wraps the text in a code block, so Discord shows it as typed, and the saved file has none.
