Slideshows without the file explorer

A slideshow is a set of images that fade into each other, as the background of a layout or in a Slideshow element. Today it's a folder you build by hand, with a file you write yourself. The Slideshows window makes, changes and deletes them: add images with a button or by dropping files, drag them into order, set how long each one shows, and watch it play. It opens from the menu bar and from every place that picks a slideshow.

What gets in the way
  • A slideshow gets made outside the game: a folder in config/fancymenu/slideshows, an images folder inside it, and a properties.txt next to that.
  • properties.txt is written by hand. A missing bracket or a missing type line, and the slideshow doesn't load. Only the log says why.
  • Images play sorted by file name, so changing the order means renaming files.
  • fadespeed is a factor, not a time: 1 fades for 5 seconds and 2 for 2.5. With 0 the slideshow stays on its first image.
  • x, y, width and height are in the file, but nothing reads them. Backgrounds and elements set their own.
  • A new slideshow or a changed file only shows up after Reload FancyMenu.
  • The name in properties.txt is what layouts ask for. Changing it empties every background and element that showed the slideshow, without a warning.
  • Choose Slideshow lists the slideshows and previews one, but it can't make, change or delete any.

The window, piece by piece

The list
One row per slideshow, sorted by name: its first image, the name, and under it how many images it has and how long each one shows. No images yet shows in amber, and missing images in red. The search finds names and image files.
The header
The name with Rename, and a line with the number of images and their size on disk. Below: Duplicate, Export as Text and Delete.
The preview
Plays the slideshow like the game does: each image stays for its time, then the next one is there and the old one fades out over it. The line below says which image is up, with Play and Pause, and how long one round takes. It only shows once there's an image to play.
Images
Every image as a picture with its place and its file name, four in a row. The one the preview shows has a blue frame, and a click shows any other. Drag one to move it, and the × that appears on it removes it. Add Images sits in the section's header. A slideshow without images shows where to drop them instead.
Playback
Show Each Image For and Fade in seconds, each with a stepper. Random Order as a switch, and Overlay Image for the one picture that's drawn on top of every image. The line below says how long one round takes.
Used in
Every layout whose background is the slideshow, every Slideshow element that shows it and Pre-Load Resources, each with Open. When nothing shows it yet, a line says where a slideshow can go.
Dropping files
Minecraft only reports files once they're dropped, so the window can't show a target while they hover (rule 118). The Images section says up front that dropping works. Dropped images go into the selected slideshow, or into a new one when none or several are selected. Right after, they're tagged New and the footer says what got added and what got left out, with Undo.
Opened from a picker
The pencil, New Slideshow and Manage Slideshows in a slideshow submenu open this window. It only manages: which slideshow an element or background shows gets picked in that submenu. A slideshow that's on the screen behind the window plays there with every change.
Several selected
How many, and how many images in all, with Duplicate and Delete for all of them. Playback sets every selected slideshow, and a value that differs shows as Mixed. Below, the selected slideshows with how many places use each one.

Make one, use one, rename one

A slideshow from scratch
1New Slideshow adds New Slideshow with its name selected. Type Seasons and press Enter.
2Drop four pictures onto the window, or pick them with Add Images.
3Drag them into order, then set Show Each Image For to 6 s and Fade to 1.5 s. The preview plays it.
4Save writes the folder and its file.
Straight from the layout editor
1Right-click a Slideshow element and open Slideshow. It lists every slideshow.
2New Slideshow at the bottom opens the window with a new one.
3Add its images and set how it plays. Save keeps it.
4It's in the element's Slideshow submenu now. Pick it there, and the element plays it.
A better name
1Select Seasons, press F2 and type Four Seasons.
2A sheet says it's used in 2 places, in a layout and Pre-Load Resources.
3Rename and Update 2 Places changes both, so they keep showing it.
4The footer says what happened, with Undo.

Special cases it handles

  • Files that were copied into a slideshow's images folder by hand show up at the end, sorted by name, so old slideshows play like before.
  • An image whose file is gone shows as Missing and gets skipped while playing. A card at the top offers to remove it.
  • PNG and JPEG work, like today. Other files dropped onto the window get left out, and the footer names them.
  • An image that's already in the slideshow doesn't get added twice.
  • A fade can't take longer than an image shows, so raising one past the other moves both.
  • When a slideshow starts, its first image changes after half the time, like today, so a menu doesn't look still for long.
  • Every image gets drawn at the size of its background or element, so one with a different shape gets stretched, like today.
  • Removing an image deletes its copy with Save, and deleting a slideshow deletes its folder with Save. Until then Undo brings them back.
  • The folder is named after the slideshow, in lowercase with _ for spaces, and gets renamed with it.
  • Overlay Image is today's overlay.png: one picture drawn on top of every image, like a frame or a logo.
  • The window never sets which slideshow a place shows. That gets picked in the place itself, in its slideshow submenu.
  • A copy gets copies of the images. Nothing shows it until it's picked somewhere.

Changes beyond the UI All approved

The window above already uses these. They change how slideshows get saved, ordered, timed and found, so each one is a rework rule.

Slideshows are made in a window Approved, rule 160
The Slideshows window writes the folder in config/fancymenu/slideshows and its properties.txt on Save, so nobody has to. The folder is named after the slideshow. Old slideshows load as they are, and changes show without Reload FancyMenu.
Slideshow images keep their order Approved, rule 161
properties.txt saves the file names in the order they play, instead of sorting them by name. Files in the folder that aren't in the list come last. Added images get copied into the folder, and a listed file that's gone shows as missing.
Slideshow timing is in seconds Approved, rule 162
Fade is a time, and 0 switches without fading. Old files with fadespeed load as 5 divided by it. x, y, width and height go away, since backgrounds and elements set them.
Slideshows know where they're used Approved, rule 163
The index of rule 87 also collects slideshow names: Slideshow backgrounds, Slideshow elements and Pre-Load Resources. Used in, the filter, the rename sheet and the delete sheet read it.
Slideshows are managed where they're picked Approved, rule 164
The slideshow submenu of rule 133 gets a pencil on every row, then New Slideshow and Manage Slideshows. All three open the window, and picking stays in the submenu. The menu bar gets a Slideshows entry too.
Changes show right away Covered, rule 38
A screen or element that shows a slideshow follows every change to it, and Cancel puts everything back.
Cancel asks only when something changed Covered, rule 68
Discard 2 changes? only shows when a slideshow changed.
Mixed selections are visible Covered, rule 25
With several slideshows selected, a number that differs shows as Mixed and a switch shows the mixed state.
