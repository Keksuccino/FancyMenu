FancyMenu · UI rework concept · file entries in context menus

See the file before you open the chooser

Every menu entry that points to a file, like an image, a sound, a video or a text file, now shows that file on the row itself: its name, a thumbnail or a play button, and a warning when it is missing. Hovering opens a preview card with the full path and where the file comes from. Clicking the row still opens the chooser right away.

The preview card

Minecraft resource
Sounds get a waveform with a play button and the preview volume. Resources from Minecraft or a resource pack show their location.
Web
The full address, wrapped, and whether it loaded. Open in Browser replaces Show in Folder.
Missing file
The card says the file could not be found, so a broken layout is easy to fix. Show in Folder still opens the folder it was in.
Video
The first frame with a play button and the length. The video plays right in the card, with the same preview volume as sounds.
Video without Watermedia
FancyMenu can't preview or play videos without Watermedia, so the card says so and offers both downloads. The file itself is kept as it is.

Placeholders in file sources

A source can contain placeholders, so the raw text is not always a valid path, address or resource location. FancyMenu resolves it live, also in the layout editor whenever it can, and only then knows which file it is and where it comes from. The row works like every other placeholder value: the { } button is tinted and a chip shows the result, here the resolved file with its thumbnail.

Resolves in the editor
The chip shows the resolved file name next to its thumbnail, and the card shows the real file. It can change while the game runs.
Only resolves in game
Placeholders like World Loading Progress have no value in the editor. The chip says in game, in grey: this is expected, not an error.
Resolves to a missing file
The chip turns red with the warning icon, just like a missing file without placeholders.
Resolved in the editor
The card shows the resolved file first, then the source text with each placeholder highlighted.
Only resolves in game
No preview yet, and the card says why. Edit Source as Text and the { } button both open the source text with placeholder support.

Behavior

  • Clicking the row opens the chooser right away, in the folder of the current file. Hovering opens the preview card and the extra actions.
  • The play button plays the sound once without opening anything; clicking it again stops it. The preview volume in the card only changes how loud previews play, never the volume the sound has in the layout. It is one saved setting, shared with the file chooser and every other sound preview, and the speaker button mutes it.
  • The row and the card always show the file as it is right now: if it gets moved or deleted, or a web image stops loading, the warning shows up the next time the menu opens.
  • Sources with placeholders resolve live in the editor whenever possible, and rows and cards update when the result changes. Choose Image keeps the placeholders when the chooser opens; Edit Source as Text edits them directly.
  • File names are never cut off; a long name makes the menu wider. Full paths only show in the card, where they wrap between folders.
