FancyMenu · UI rework concept · Messages, Welcome and About

Small windows that say more

FancyMenu asks questions, reports errors, greets new users and thanks its people in small windows. Messages get a title, a clear text and buttons that say what they do. The Welcome window helps with the first steps instead of only pointing to the docs, and Credits becomes About, a window with FancyMenu's version at hand.

What gets in the way
  • Every message is called Info, Warning or Error and has one block of text. Its buttons are OK, or Cancel and Accept, whatever it asks.
  • A question that makes you wait keeps its button grey, and only a tooltip says for how long.
  • An error from an action doesn't say which script ran it, so you have to search for the button or listener that did.
  • Messages that belong to a window open as one more window on top of it.
  • The Welcome window is a block of text with one button, Open Documentation. After that it never shows again.
  • Credits is a full screen that replaces the screen you're on: one long centered text, a third of it the same font license seven times.
  • Credits doesn't show FancyMenu's version, which every bug report needs.

The windows, piece by piece

A message
The same layout as a sheet, in a window of its own: an icon tile, the title, the text and the buttons under each other, the main one first. Only Close works in its title bar, since a message has one size.
Tones
Blue for a plain question, amber for one that can break something, red for errors and for buttons that delete. The word in the title bar stays Info, Warning or Error.
A button that waits
It says how long, like Override in 2 s, and a fill moves across it. Once the time is up it turns into Override.
An error
The title names what failed. The text says why, and which element and script ran it. A line in code font gives the exact place. Show Script opens the script editor there, Copy Details copies all of it with the log lines that belong to it.
Welcome
The logo, four numbered steps, the Appearance choice, and three buttons: Start Customizing closes the window, Open the Docs and Join the Discord open in the browser.
About
FancyMenu with its version line and Copy Version Info, the line in memory of UwUCookies, then Lead Developer, Patreon Supporters, Alpha and Beta Testers, Special Thanks, Buddy's Assets, Fonts and Copyright.

Special cases they handle

  • Closing a question with the red button answers Cancel, like today.
  • Enter presses the main button and Esc cancels, like today. While the button waits, Enter does nothing.
  • Info and Error messages have one main button, OK. An error can have Show Script and Copy Details below it.
  • An error that no script caused, like a file that can't be read, has no Show Script.
  • The Welcome window shows on the first title screen and not in modpack mode, like today.
  • Appearance changes FancyMenu's theme right away, also for the menu bar behind the window.
  • About reads its names from the same file as today, so adding a supporter is still one line.
  • Copy Version Info copies one line, like FancyMenu 3.10.0, Minecraft 1.21.11, NeoForge.

Changes beyond the UI

The windows above already use these, so each one is a rework rule.

Messages have a title, a text and named buttons New, rule 140
Dialogs.openMessage takes one text and a style, and the buttons are fixed. Callers pass a title, a text, the label of the main button and whether it deletes.
A button that waits counts down New, rule 141
setDelay keeps the button off and puts Clickable in N seconds.. into a tooltip. The button shows the seconds and a fill instead.
Errors say what ran them New, rule 142
An action that fails knows its script and what runs it (rule 81), so its message names the element and step, and Show Script jumps there.
The Welcome window can come back New, rule 143
Help gets a Welcome entry. The window itself still shows once, on the first title screen.
Credits becomes About, a window with the version New, rule 144
CreditsScreen becomes a window called About, and credits_and_copyright.md gets read as sections and names instead of one Markdown text.
Messages are sheets wherever a window is open Covered, rule 134
The standalone window is only for messages that have no window to slide down from.
Main buttons say what they do Covered, rule 40
Override, Clear Tracks and Start Customizing instead of Accept and OK.
