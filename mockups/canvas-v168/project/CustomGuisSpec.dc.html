FancyMenu · UI rework concept · Custom GUIs

Your own screens, in one window

A custom GUI is a screen of your own that a layout fills. Manage Custom GUIs, Build or Edit Custom GUI and Manage Overridden Screens become one window: a GUI's settings sit next to the list, together with its layouts, the screen it replaces and the places that open it. Open shows a GUI behind the window while you change it, and renaming or deleting one takes its layouts along.

What gets in the way
  • Three windows for one job: the list, the settings of one GUI, and the screens that GUIs replace. New GUI and Edit GUI hide the list while their window is open.
  • The list shows identifiers and nothing else. It doesn't say what a GUI is, whether it has a layout, or what opens it.
  • The six settings are cycle buttons with long labels, like Popup Mode Background Overlay: Enabled. Two of them only do something while another one is on.
  • A new GUI is an empty screen. To give it a layout you open it, close the window and make the layout from the menu bar.
  • Open GUI saves every change in the window first, so Cancel can't take them back afterwards.
  • Renaming a GUI leaves its layouts and its override rule under the old identifier. It opens empty, stops replacing its screen, and scripts that open it show an error.
  • Delete GUI asks every time, says it can't be undone, and leaves the GUI's layouts and override rule behind.
  • A GUI can get the identifier of a real screen, like pause_screen. Both then share their layouts.
  • Override rules sit in their own window, apart from the GUI they belong to.
  • Cancel throws away every change without asking.

The window, piece by piece

The list
One row per GUI, sorted by identifier: an icon for a screen or a popup, the identifier, and under it the title, or the screen it replaces. No layout yet shows in amber. An eye marks the GUI that's open behind the window.
The header
The identifier with Rename, and a line that says whether it's a screen or a popup, how many layouts it has and which screen it's shown instead of. Below: Open, which turns into Close, Duplicate and Delete.
Screen
Title is drawn at the top of the screen and takes placeholders, $$ names and localization keys, so its field opens the text editor too. Close with Esc says that players need a button that closes the GUI while it's off. Pause the Game works in singleplayer worlds.
Behind the GUI
Show the World: in a world, the game shows behind the GUI instead of the panorama. Popup: the screen it opens from stays visible. Each has one switch below it, Blur and Dim It and Blur the Screen Behind, that only shows while it's on.
Layouts
The layouts made for this GUI, with Off on the ones that are turned off. A double-click or the button on the row opens one in the layout editor, and New Layout starts one. A GUI without layouts says that it opens as an empty screen.
Shown Instead Of
Only there for a GUI that replaces a screen: the screen with its identifier, and Stop Replacing. The line in the header and the second line in the list name the screen too.
Used in
Every script that opens the GUI, grouped by layout, listener and scheduler like in Variables and Schedulers, each with Open. When nothing opens it, a line says how: Open Screen or Custom GUI in any script, or /openguiscreen with its identifier.
Several selected
How many, and how many of them are popups, with Duplicate and Delete for all. The six switches set every selected GUI and show a mixed state with a count when they differ. Below, the selected GUIs with their layouts.
The footer
Which GUI is open behind the window, and that changes show on it right away. After a change, what changed, with Undo. Cancel and Done on the right, like today: Done saves, Cancel puts everything back.

Make one, tune one, rename one

A new screen
1New GUI adds new_gui with its identifier selected. Type quest_log and press Enter.
2Type its title, and turn Pause the Game off so the world keeps running behind it.
3New Layout opens the layout editor on the empty GUI. Add the quest list and a Back button.
4Pick quest_log in Open Screen or Custom GUI wherever it should open. It shows up under Used in.
A popup that looks right
1Select credits and press Open. It shows behind the window, on top of the title screen.
2Turn Blur the Screen Behind off. The title screen behind it gets sharp right away.
3Not better? Undo in the footer, or Ctrl+Z, blurs it again.
4Done saves it. Cancel puts every GUI back and returns to the title screen.
A better identifier
1Select quest_log, press F2 and type quests.
2A sheet says it's used in 2 places, in a layout and a listener, and that its 2 layouts move with it.
3Rename and Update 2 Places changes both scripts to quests, so they keep opening it.
4The footer says what happened, with Undo.

Special cases it handles

  • Open uses the screen you're on as the one the GUI opened from, like today. From the title screen no world is loaded, so a GUI that isn't a popup shows the panorama.
  • A popup needs a screen to stay on top of. Opened by a key or a command while playing, there is none, and Show the World decides what's behind it.
  • Without Show the World, the panorama is always blurred and dimmed, so Blur and Dim It has nothing to switch and hides.
  • Pause the Game only pauses singleplayer worlds that aren't open to LAN, like Minecraft's own menus.
  • Cancel closes a GUI that Open put behind the window and goes back to the screen you came from. Done leaves it open.
  • Deleting the GUI that's open behind the window closes it.
  • New Layout and opening a layout save the window's changes like Done and close it, because the layout editor needs the GUI the way the window shows it.
  • A copy gets copies of the layouts. The screen a GUI replaces stays with the original, since only one GUI can replace a screen.
  • Override rules get added like today: This Screen › Override With Custom GUI on the screen itself, with Advanced Customization Mode on. Stop Replacing takes effect with Done, like every change here.
  • Identifiers take lowercase letters, numbers, . _ and -, like today. Spaces turn into _ while typing.
  • A GUI from an old file that has a real screen's identifier keeps working. Its row is red, and a card explains what the two share and offers Rename.
  • Used in can't see /openguiscreen in command blocks or on servers, so a GUI that nothing uses may still be opened from there.

Changes beyond the UI

The window above already uses these. They change how custom GUIs get saved, renamed, deleted and found, so each one is a rework rule.

Open shows a GUI without saving New, rule 124
Open GUI writes every GUI in the window to custom_gui_screens.txt before it opens one. Open hands the screen the window's own copy instead, which a screen can show without it being saved, so nothing gets written before Done and every change shows on the open GUI right away.
Custom GUIs know where they're used New, rule 125
The index of rule 87 also collects screen identifiers: every variable with the lookup fancymenu:screens, like the values of Open Screen or Custom GUI and Disconnect, also from addons. Used in, the Not Used filter, the rename sheet and the delete sheet read it.
A GUI's layouts and override rules follow it New, rule 126
Layouts and override rules find a GUI by its identifier, and today renaming or deleting a GUI touches neither. Renaming moves both to the new identifier, deleting deletes both once Done saves, and Duplicate copies the layouts.
Custom GUIs can't take a screen's identifier New, rule 127
Screens and custom GUIs are found by the same identifier, and custom GUIs get checked first. A GUI named pause_screen shares the pause screen's layouts, and scripts that open pause_screen get the GUI. New identifiers like that are refused.
New GUIs get an identifier to type over New, rule 128
New GUI adds new_gui, then new_gui_2, right away with today's default settings, instead of opening a form with an empty identifier.
Layouts start in the Custom GUIs window New, rule 129
New Layout makes a layout for the GUI and opens the layout editor on it, without the GUI being open. The editor already takes any screen: Ctrl+Alt+L, which reopens the last edited layout, builds a custom GUI for it the same way.
Override rules sit with their GUI New, rule 130
Manage Overridden Screens goes away, and Custom GUIs in the menu bar opens the window directly instead of a submenu. Rules are removed on their GUI and still added on the screen itself.
Cancel asks only when something changed Added to rule 68
Discard 2 changes? only shows when a GUI changed. Opening one behind the window doesn't count.
Mixed selections are visible Covered, rule 25
With several GUIs selected, a switch that differs shows the mixed state, and flipping it turns it on for all of them.
