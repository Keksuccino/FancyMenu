FancyMenu · UI rework concept · script editor

A script editor that reads like a sentence

Every step is one line you can read out loud: Play Audio click.ogg at 80%, If intro_seen is not true. Values and conditions are tokens you click to edit right where they are. Adding happens from one searchable menu, several steps can be selected, copied, wrapped and turned off at once, and problems show up on the step that has them instead of failing silently in game.

What gets in the way
  • Values show how they are stored, not what they do: Play Audio and Show Toast show JSON, Set Variable shows intro_seen:true, Send HTTP Request shows url|||POST|||{…}|||… and long values run off the row.
  • Conditions only list requirement names. IF (Is Variable Value (FM Variable)) doesn't say which variable, which value, or that it's negated, and groups lose their and/or.
  • Editing a value needs a double-click on its text, which nothing hints at. Actions with their own editor hide the whole script editor while it's open.
  • The add menu is one alphabetical list of about 60 actions without descriptions. The full list with search is a separate window. New actions get example values like example.menu.identifier that quietly don't work.
  • Adding an If opens the Manage Requirements window first, and cancelling it drops the If.
  • One step can be selected at a time. Copy and paste only work for a single action inside the same window, and copying a block flashes a big "not allowed" icon.
  • No search, no way to turn a step off for testing without deleting it, no way to put steps into an If or a folder after the fact.
  • Full-color rows and two lines per action even without a value (Value: NONE). The minimap shows colored blocks, but no names, problems or search results.
  • Nothing says what runs the script, and listener scripts don't show the $$ variables they get.

A step, piece by piece

folderFolders and unknown actionsGray, because they don't do anything on their own.

The colors come from the UI theme fields the script editor already has (actions_entry_background_color_*), now used for the tile instead of the whole row.
Tokens read like text and edit like fields
  • A token is the value itself on a soft tint. On hover it gets the field outline. A click on a text variable edits it right there, any other variable opens the action's form with a control for its type.
  • Typed variables show what they are: a play button for sounds, the element's icon, On or Off for switches, and units like 80% or 3 s.
  • Placeholders show as the same chips as in the text editor, $$ variables as small code chips, and & color codes with a swatch.
  • Empty values show what goes in, dashed: URL, Add a condition. A While without a condition is red, because it freezes the game for 3 seconds.
  • Long values wrap onto more lines instead of getting cut off.
  • The words around the tokens come from the step's row sentence in the current language, like Set Variable {variable} to {value}, so every language can use its own word order. Words after the first token are dimmed, so the values stand out.
  • Thin guides connect a block with its steps. Hovering or selecting an If lights up the guides of its whole chain.

Typed variables

Action variables use the same types and controls as placeholder variables (Keksuccino/FancyMenu#1849, rule 70). Every typed control keeps a { } button to type placeholder text instead, and switching back keeps the value when it still fits the type.

TEXTEdited right in the row when it's an action's only variable, otherwise a field in the form. { and $$ suggest placeholders and event variables.
BOOLEANA switch. The row says On or Off.
INTEGERWith a range, like Volume 0 to 100%, the slider context menus use. Without one, a number field with its unit and a stepper, like the HTTP timeout. The stepper moves in steps that fit, like 100 ms for times (rule 18).

Blocks read like sentences

If, Else If, Else
If [condition] and [condition]. Each condition is its own sentence, and Is Not uses its negated one, like intro_seen is not true. Else If works the same, Else has nothing to fill in. Click a condition to flip Is and Is Not or open Manage Conditions for the rest. Each branch collapses on its own.
While
While [condition]. Its help says it stops after 3 seconds, because it runs all at once and holds the game until then. Without a condition the token turns red.
Delay Gate
Delay Gate opens after [3000 ms]. Help in one sentence: skips its steps until the time has passed since the script first got here, then runs them every time.
Execute Later
Execute Later after [800 ms]. Runs its steps once the time has passed, while the rest of the script goes on. Hovering a time shows it in seconds.
Folder
The folder name in bold. Collapsed folders show how many steps they hold. Double-click or Enter renames, Ctrl+G wraps the selection in a new folder.
Comment
Italic text with a speech bubble. Comments wrap like any other text and never run.

Adding steps

One menu for everything
  • The Add button in the toolbar, A, Add Step in the right-click menu and the empty state all open the same menu.
  • Blocks first, then Favorites, then the 3 actions you used last, then all actions by category. Typing searches every action by name and description and shows its category on the right.
  • Hover help explains each entry, with an example value where it helps. Hovering an action shows a star: click it to add it to Favorites.
  • Actions that can't be used in this layout don't show up, like today.
Where a new step goes, and what happens next
  • Right below the selected step. When a block is selected, at the top of that block. With nothing selected, at the end of the script. Pasted steps follow the same rule, and so does a click on an empty block's "Click to add a step".
  • Actions start with real defaults where there is one, like 100% volume, and empty otherwise, with their example as a hint ("like https://example.com") instead of a value that silently doesn't work.
  • A single text variable is ready for typing right away, every other action opens its form. An If or While opens its conditions, a folder starts with its name selected.

Minimap

What it shows
  • The whole script as small bars, one per row the list shows: the step's color, then a bar as long as its text. Blocks get their own color, comments are fainter and steps that are off are dimmed. Collapsed blocks stay collapsed, because the minimap mirrors the list.
  • Folder names sit on their rows as small labels, so a long script reads like a table of contents.
  • Marks on the right edge for problems and find results, and the selected steps as a band.
  • The box shows what's visible in the list right now.
  • It fits the whole script as long as the rows stay readable. Longer scripts keep that size and the minimap scrolls along with the list, while the marks then show the whole script.
What you can do with it
  • Hovering shows a preview of that step with the steps around it and where it sits, like Quests › If › Else If. Its block gets outlined in the minimap, and its guide lights up in the list.
  • Clicking jumps there and selects the step. Dragging the box scrolls, and so does the mouse wheel over the minimap.
  • Dragging steps over the minimap scrolls the list to that spot, so a step can travel from the top of a long script to the bottom in one drag.
  • The minimap button at the right end of the toolbar, right above the minimap, hides or shows it, and the editor remembers that. Without it, the marks move into the list's scroll bar.

Special cases it keeps handling

  • Else If and Else belong to their If. They can't be dragged out of the chain, Alt+↑/↓ only reorders Else Ifs, Else always stays last, and Add Else is off when there already is one. Deleting the If deletes its chain.
  • Comments can't hold steps, so dropping on a comment puts the step after it.
  • Actions from a mod that isn't installed stay in the script as Unknown action with their id and variables. They get skipped and saved back unchanged, while today the next save deletes them (rule 86). Their warning says which mod they come from.
  • Deprecated actions show a Deprecated chip in the Add menu and on their step, with what to use instead in the help.
  • Values with placeholders stay plain text underneath. Tokens, summaries and forms only change how a value is shown and edited.
  • Listener scripts list the Event Variables of their event, like $$key_name, behind a button in the footer. They also come first in the $$ suggestions. Checkbox and Slider scripts suggest $$value first, labeled Checkbox value or Slider value. It's their current value, so it needs no button of its own.
  • Actions with a big editor of their own, like Send HTTP Request, open it as a child window on top. The script editor stays visible behind it, dimmed.
  • Dragging near the top or bottom scrolls the list. Holding Alt while dropping copies instead of moving.
  • Collapsing is not an edit: it's saved with the script like today, but Undo skips it.
  • Cancel and the close button only ask about discarding when something changed.

Changes beyond the UI All approved

The editor above already uses these. They change the action API or what gets saved, so each one is a rework rule.

Actions describe their variables Approved, rule 70
An action can split its value into variables, each with a type from the same enum placeholders get in #1849, plus a sentence for its row (rule 71). Set Variable gets Variable and New value, Play Audio gets Sound, Volume and Channel. Actions that don't do this keep one text variable with the raw value, and saved values don't change.
Actions get categories Covered, rule 71
Actions get a category from the one category list that placeholders, conditions and events share, so the Add menu can group them. Addons can add their own categories.
Steps can be turned off Approved, rule 76
A Runs switch on every step, and Ctrl+/ for the selected ones. Steps that are off stay dimmed with an Off chip and get skipped. Turning off a block skips everything inside it, and turning off an If skips its whole chain. Each step that's off saves one extra line, so old scripts load with everything on.
New actions start empty Covered, rule 71
getValuePreset() becomes the hint in the empty field instead of the starting value, the same idea as real placeholder defaults in #1851.
Collapsing is view state Approved, rule 77
Still saved with the layout, but Undo skips it and it doesn't count as a change. Else If and Else get their own collapse arrow and saved flag, so collapsing an If only hides its own steps. Today collapsing is an undo step, and collapsing an If also hides its Else If and Else.
Event variables explain themselves Covered, rule 71
Event variables, today AbstractListener.CustomVariable, get a short description and an example, so the editor can list them. Today they are only described inside the long description of their event (rule 103).
Shorter names for the variable actions Approved, rule 78
Set Variable Value (FM Variable), Delete Variable (FM Variable), Clear All Variables (FM Variable) and the Is Variable Value (FM Variable) condition become Set Variable, Delete Variable, Clear All Variables and Is Variable Value, matching Get Variable (rule 57). Their identifiers stay the same.
Scripts know what runs them Approved, rule 81
The editor gets told who runs the script, for the line at the top like Runs when Play is clicked, and which $$ names come with it, like the Event Variables of a listener's event or Checkbox value. Today it only gets the script itself. Plan: Keksuccino/FancyMenu#1857.
Variables know their units Approved, rule 85
Number variables get a unit, a step and a display scale, so a volume saved as 0.8 shows as 80% and a time as 3 s. File variables get a media kind, which brings the play button for sounds. Plan: Keksuccino/FancyMenu#1849.
Nothing from a missing mod gets lost Approved, rule 86
Actions from a mod that isn't installed stay in the script, warn with the name of their mod and get saved back unchanged. Today they're left out while loading, so the next save deletes them: Keksuccino/FancyMenu#1862.

Bugs found in today's editor Fix during the rework

  • Dragging a step above the top of the list never scrolls up: the check compares the pointer's x with the list's top y (mouseX <= getInnerY() in ActionScriptEditorWindowBody.renderBody). Keksuccino/FancyMenu#1852
  • Move Up and Move Down do nothing for folders and comments, because moveUp and moveDown only handle actions, If, While, Delay Gate, Execute Later and Else If. Keksuccino/FancyMenu#1853
  • A While that hits its 3 second timeout once never runs again until the layout reloads: hasTimedOut is only reset after a run that finishes, and a timed-out While returns before it can get there. Keksuccino/FancyMenu#1854
  • Adding a step to a selected block puts it at the end of the block, dropping one on a block puts it at the start. Keksuccino/FancyMenu#1855
  • Cancel always asks whether to discard, even when nothing changed. Keksuccino/FancyMenu#1856
