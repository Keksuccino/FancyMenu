FancyMenu · UI rework concept · carry these into the code

Rules for the real rework

Everything we agreed on while making these mockups. The rules apply to the whole UI, not only to the screens shown here, and the list grows whenever we settle something new. What to fix during the rework is on the board below.

Principles

1One design language everywhere
Every screen, menu, panel and dialog in FancyMenu speaks the same design language: the same controls, surfaces, sizes, spacing, colors, type and motion, defined once and reused everywhere. Consistency across the whole UI matters more than any single screen looking special. When something new is needed, like a new kind of component, it's built from the parts that already exist and then added to the language, so the next screen reuses it instead of getting its own one-off look. Two things keep their own look: the toasts of Show Toast, which are Minecraft's own toasts, and the Buddy with its status screen, which isn't a FancyMenu UI.
See: Controls & window chrome, Surfaces, and every rule below
2Everything fits and connects
Bars, gutters, lists and panels always fill the space they belong to and connect cleanly to the parts around them, like the text editor's line numbers running from the toolbar down to the status bar. Nothing ends with an odd gap or looks like it was just dropped in.
See: Text editor
149The mockups are the measure
Every size, padding, gap, radius, text size and color in these mockups is meant. The real UI copies them as closely as it can, at UI scale 1 and growing with it, instead of picking new values while building. The section Exact measures lists the numbers, and the stylesheet of the mockups, fm-ui.css, holds every one of them. Where the game can't draw something the same way, the nearest thing it can draw is fine.
See: Exact measures

Shared components

3Every element is a shared component
Buttons, icon buttons, fields, pop-up buttons, segmented controls, switches, sliders, steppers, chips and tags, list rows, groups, headers, menus, popovers, sheets, toolbars, footers, callouts and empty views each exist once, as one component with one API. A screen only places and configures them and never draws its own copy, so a fix or an improvement lands everywhere at once. Variants are options of their parent instead of separate components: a button can be small, icon-only, primary, tinted or destructive, a field can be multi-line, mono or a search field, and a chip can be a tag, a value or code. Controls bring their own text size, so a button looks the same in a window, a menu and a popover. When a screen needs something its parent can't do yet, the parent gets it as a new option that every other screen can use too. The mockups are built the same way, so their components carry straight over to FancyMenu.
See: Controls & window chrome, Context menus · today and proposed, and every screen
4One type scale
Text comes in six sizes: 10.5 px bold for tags and small capital labels, 11.5 px for notes, hints and status bars, 12 px for section labels, small buttons, values on the right of a row and the text in cards and popovers, 13 px for everything else, 15 px bold for the titles of sheets and empty views, and 20 px bold for the name at the top of a detail view, like a profile or a variable. Everything uses Noto Sans, the font FancyMenu already renders smooth text with. Code, identifiers and values use Noto Sans Mono (rule 83) at 12 px, or 11 px next to small text.
See: Controls & window chrome, Profiles, Variables · checking coins
5Corners follow the height
28 px controls round by 7 px, 22 and 24 px ones by 6 px, and anything smaller by 5 px. One-line list rows round by 6 px and two-line rows by 8 px. Menu rows round by 5 px, so they sit evenly inside the menu's 10 px corners. Previews round by 8 px, groups, cards, menus and popovers by 10 px, and windows and sheets by 12 px. Thumbnails round by 4 px.
See: Surfaces, Controls & window chrome
6One icon set: Material Symbols
Every icon is a glyph from Material Symbols Rounded SemiBold, the icon font FancyMenu already bundles, and code picks it by its name, like MaterialIcons.DELETE, so the mockup and the mod share one list of icons and nothing gets drawn by hand. Icons use the outlined style. The filled style is only for an active favorite star and for play and stop in previews. Where FancyMenu already uses an icon for something, the rework keeps it, like stacks for profiles, gallery_thumbnail for layouts and hearing for listeners. Icons are 15 px in rows, menus and icon buttons, 16 px in toolbars and window titles, 14 px in text buttons, small buttons and editor panels, and 12 px for chevrons.
See: Script editor · a button’s click script, File browsers · Choose Image, Menu bar · layout editor
7Lists share one row
The Layers panel, the file browsers, Profiles, Variables, Listeners, Schedulers, the text editor's placeholder list and the lists inside popovers all use one list row: the same light tint on hover, the same accent selection, and tags and icons that turn white on the selected row. Rows only differ in height and what they show: one-line rows are 26 to 32 px tall, two-line rows 46 to 52 px.
See: Layout editor · a button selected, Profiles, Variables · checking coins, Listeners · the quest log key, running live, Schedulers · fireflies, running live, File browsers · Choose Image
8Bars share one layout
Window footers show a note or status on the left and their buttons on the right, Cancel before the confirm button, each at least 92 px wide and 10 px apart. A line separates the footer only where the content above it scrolls or is split, like in the file browsers and Variables. Toolbars are 48 px tall with 28 px icon buttons 4 px apart and a thin divider between groups. The action bar under a title and the actions at the bottom of a popover use the same buttons 8 px apart, with icon-only buttons where the icon says it all, like Delete.
See: File browsers · Choose Image, Variables · checking coins, Text editor · editing a placeholder chip
9Headers share one layout
A section inside a window has a 12 px bold label 6 px above its group. A detail view, like a selected profile or variable, starts with its name in 20 px bold, a 12 px meta line under it and its action bar 12 px below that. Sheets and empty views start with a 15 px bold title followed by 13 px text. Warnings inside a window or sheet use one callout: a tinted box with 12 px text.
See: Profiles, Variables · checking coins, Variables · renaming a variable that layouts use
152Progress looks the same everywhere
What is happening stands on the left and the percent on the right, the bar runs under them, and below it the current step stands on the left and the time left on the right, like About 13 s left. Percents have no space before the sign.
See: Profiles · states, Pre-Load Resources · loading, AFMA Creator · creating

Text and labels

10Never cut labels off
Labels never get shortened with "...", and labels that open a dialog don't end with dots either. If a label doesn't fit, its container grows. Previews of long values are different, because a value can be any length: a long Text Content on the right of a menu row or a variable's value under its name in a list ends with … where it runs out of room, and opening the entry or selecting the variable shows all of it.
See: Context menus, Menu bar, Variables · checking coins
11Menus fit their longest label
Context menus and menu bar menus are always as wide as their longest full label, and resize right away when entries or labels change.
See: Context menus
12Labels next to their controls
A label sits on the same line as its control, macOS style, instead of above it or baked into a button.
See: Redesigned screens
13Help never repeats the label
Hover help explains what an entry does. It never shows the entry's name again.
See: Layout editor · Text element menu
14Texts follow the mockups
Wherever a mockup words something differently than FancyMenu's language files do today, the language files change to the mockup's wording: entry names, buttons, hints, notes, messages and window titles, like Search variable.. becoming Search 12 variables, or Clear Variable on Game Launch becoming When the game starts with Keep value and Reset. en_us.json changes first, and every other language file follows with a natural translation, not a word-for-word one. Language keys can be renamed or regrouped along the way, while saved identifiers stay the same (rule 55).
Applies to every board in this concept
153Search fields say what they search
A search field names what it looks through, with the count where there is a list: Search 13 variables, Search settings, Search backgrounds. A find bar says where it looks, Find in text or Find in steps, and its second field says Replace with.

Controls

15Cycle buttons are replaced
2 to 4 short options become a segmented control, or up to 6 when each one is a single symbol or icon, like the comparisons of Is Number. More options become a pop-up button with a chevron, or in menus a submenu with a checkmark on the current option.
See: Redesigned screens, Context menus, AFMA Creator · fine-tuning Smallest File
16On or off is a switch
Switches show the state at a glance, instead of colored Enabled and Disabled text.
See: Context menus, AFMA Creator · fine-tuning Smallest File
17Numbers with a range are sliders
A number with a fixed range, like a volume from 0 to 100% or an opacity, is a slider with its value right next to it, the same one context menus use, in menus, forms and windows alike. Dragging updates the setting live and counts as one undo step, not one per tiny move. Numbers without a range, like a time in milliseconds, are a number field with their unit and a stepper, like the HTTP request's timeout.
See: Context menus · today and proposed, Script editor · Play Audio's variables
18Steppers take steps that fit
Stepping by 1 is fine while a value stays between −10 and 10. Anything bigger takes far too many clicks that way, so a stepper steps by an amount that fits the value, like 5 seconds for a timeout or 100 ms for a time, and its buttons say the step on hover. When a value has a range, it gets a slider instead (rule 17), and steppers are only used where neither fits better.
See: Controls & window chrome, Edit HTTP Request, Script editor · today and proposed
19Scroll bars look the same everywhere
Everything in FancyMenu's own UI that scrolls, menus included, shows the same scroll bar as long as there's more to see: a round thumb 6 px wide with a 3 px inset and at least 28 px long, that grows to 8 px with a soft track on hover and gets darker while it's dragged. It never hides until you scroll, so a list that goes on always looks like one, and its colors come from the theme. Lists that show problems or find results put a mark for each into their scroll bar, or into the minimap where there is one. Elements in layouts keep their own Scroll Bar Style.
See: Controls & window chrome, Script editor · a long script and its minimap
20Colors show a swatch
Every color row shows a small swatch of the current color next to its hex value, so nobody opens the picker just to see it. Transparent colors show over a checkerboard. Colors whose default comes from the UI theme show that color and its hex like any other value.
See: Menu bar · layout editor (Window menu), Context menus · today and proposed, Color picker
21Every color format is editable
Hex, RGBA and HSV can all be typed into, and changing one updates the others right away. Hex takes #RGB, #RGBA, #RRGGBB, #RRGGBBAA and color names. Text that isn't valid yet stays in its field, marked red, instead of being replaced while you type.
See: Color picker
22Files show what they are
Rows that point to a file show its name with a thumbnail for images and videos or a play button for sounds, and None or Mixed like other values. Hovering shows a preview card with the full path, wrapped and never cut, plus the source and details. Missing files are flagged in red. A list with a thumbnail slot, like Pre-Load Resources, shows a note icon there for a sound and plays it from the details. Sources can contain placeholders: the row then shows the resolved file in a chip with { } tinted, and a placeholder that only resolves in game says so instead of looking like an error.
See: Context menus (Image element menu, file entries spec), Pre-Load Resources · a panorama
23Special cases look normal
When an entry works differently under the hood, it still looks and behaves like every other entry of its kind. A color that falls back to the UI theme shows that color, its hex and the usual reset arrow, not a special "Default" state, and it keeps showing its normal color while Invert Background Colors is on.
See: Menu bar · layout editor (Window menu)
24Placeholder support stays everywhere
Every setting that takes placeholders keeps it: the { } button switches to placeholder text, and a chip shows what it resolves to. This is also how booleans keep their third Manual state.
See: Layout editor · Text element menu
25Mixed selections are visible
When the selected elements disagree, the switch knob sits in the middle and values say Mixed.
See: Context menus · today and proposed
26Rows show their current value
Menu rows show their value on the right, so nobody opens a dialog just to check it. A reset arrow shows up on hover when the value isn't the default. Every row shows its state, not only the exceptions: On as well as Off.
See: Context menus
154Where text buttons have an icon
Footer buttons never have an icon. A button that adds something always starts with a plus, and every button of the action bar under a detail title has an icon. Other text buttons may have one where it helps.
See: Variables · checking coins, Schedulers · fireflies, running live, Script editor · empty script

Menus

27Every menu is the same menu
Context menus, menu bar menus, pop-up buttons and the suggestions while typing are all the same menu, built with one API: the same rows, checkmarks, hints, keys, search, edges and grow-in. A pop-up button's choices are checkmarked rows with their hint on the right. Its menu opens 4 px below it, is at least as wide as the button, and opens upward near the bottom of a window. When one place needs something the others don't, like the key hints under suggestions or an icon next to each choice, the shared menu gets it as an option instead of that place building its own.
See: Context menus · today and proposed, Controls & window chrome, Edit Profile, Text editor · suggestions while typing {
28Submenus forgive diagonal moves
While the pointer heads toward an open submenu, crossing other rows doesn't switch or close it for 350 ms. Entering the submenu cancels the switch, stopping on a row applies it after the grace time, and moving straight up or down switches instantly.
See: Menu bar, Layout editor · background menu
29Sections and separators match
Named sections use a centered label with a line on each side. Plain separators use the same light line, and both have exactly 12 px of space above and below.
See: Context menus
30Every menu is searchable
Typing in any menu or submenu searches it. The text goes to the menu under the pointer; with the pointer outside the menus, to the last menu you searched in, otherwise the main menu. While navigating with the arrow keys, it goes to the menu you are navigating. Matches are highlighted, section headers stay with their matches, and the menu keeps its width while you type.
See: Context menus · today and proposed, Menu bar
31Long menus show the search field
Menus with more than 10 entries show the search field from the start. Shorter menus keep it hidden until you start typing or press Ctrl+F, which also hides it again.
See: Context menus, Menu bar
32Growing lists collapse
Lists that can grow, like a screen's layouts, sit right in the menu while they are short (5 entries or fewer). Longer ones collapse into one row that shows the count and opens a searchable submenu.
See: Menu bar · customization overlay with 52 layouts
33Destructive actions go last
Delete, Kill-Switch and similar actions are the last row of their menu, in red.
See: Context menus, Menu bar
34Menu titles switch on hover
While a menu bar menu is open, moving to another title opens that menu without another click.
See: Menu bar

Windows and layout

35macOS window chrome
Traffic lights sit top left, and their symbols appear on all three at once when hovering the group. The window icon and title are centered.
See: Redesigned screens
36Exact window and menu edges
Windows, sheets, menus, popovers and tooltips use exactly the corner radius, outline, inner highlight and shadow from the Surfaces reference below, in both themes and both materials. FancyMenu draws these differently today, and they carry most of the macOS feel, so no surface invents its own edge or shadow.
See: Surfaces, below
37Same sizes and spacing everywhere
Buttons, fields, pop-up buttons and segmented controls are all 28 px tall with a 7 px radius, and their text uses the regular weight. Window content, footers included, is inset 22 px from the window edge, so the buttons line up with the groups above them. Sections are 18 px apart, a section label sits 6 px above its group, and a note 7 px below it. Gaps come from one scale: 4 px between the buttons of a toolbar, 8 px between controls in a row or an action bar, 10 px between footer buttons and 14 px between a label and its control. Toolbars sit 12 px from the window edge. Small tags, like file types or Active, share one chip style.
See: Controls & window chrome, Surfaces
38Live edits say so
Windows that change something on screen while you edit it show the change right away and say what previews live. Cancel, closing the window and Esc put everything back; the confirm button keeps it as one undo step.
See: Color picker, Listeners · today and proposed, Schedulers · today and proposed
39Browsers share one layout
Every file, folder and resource browser uses the same window: Back, Forward and Up, a Places button, a clickable path and search on top, a list with thumbnails, the shared preview on the right. The Places menu lists drives (only when the browser may leave the game folder), recent folders shared by all browsers, and common places.
See: File browsers
40Main buttons say what they do
Confirm buttons are named after the action, like Choose, Save, Replace or Use This Folder, instead of OK or Done. A window or message that only shows something has one button, Close. A destructive action, like replacing a file, turns the button red.
See: File browsers, Color picker, AFMA Creator · created
41Core actions are easy to find
The main actions of a screen, like New and Import in Profiles, are clear, prominent buttons, never small icons in a corner.
See: Profiles
42No space wasters
No headers or decorations that only repeat what is already visible, like an element-name header on top of an element menu. Simple lists beat crowded category grids.
See: Context menus
43Empty views are text only
A view with nothing in it yet, like an empty list, a script without steps or a search without results, shows only text: a short title, a sentence or two about what goes there, and the button that adds the first thing when there is one. No icon or illustration sits above it. A manager may add up to three short example cards under the text, as long as they are text only.
See: Script editor · empty script, Variables · no variables yet
150New adds right away
New makes the thing at once and selects it, with its name ready to type over, and the footer offers Undo. Where a kind has to be picked first, like an event or a file, New opens a menu and adds after the pick. No manager asks in a sheet first.
See: Variables · new, Schedulers · new, Custom GUIs · new
151Several selected, one view
With several things selected the details show how many there are, one summary line, the actions that work on all of them, the settings they share, and a list called Selected with each one's state on the right.
See: the Several selected boards of the managers

Editors

44The Inspector is the menu, docked
Editors show the selection's settings in a docked Inspector, built from the same rows as its right-click menu, so both always match. Small values like numbers, names, switches, choices and anchors get edited right in their row. Only big editors open a window: text, scripts, conditions, colors and files. With nothing selected, the Inspector shows the settings of what is being edited as a whole, like the layout, and its search finds any setting by name.
See: Layout editor · a button selected, Layout editor · nothing selected
45Panels dock, nothing floats
No editor has floating panels: not the layout editor, the text editor, the script editor or any editor added later, so don't add one. What stays open next to the work is docked to an edge of its window, like the placeholder list of the text editor and the minimap of the script editor, and only menus, popovers and tooltips open on top. In the layout editor, today's floating widgets become docked panels: Layers on the left, the Inspector on the right and the Timeline below, and the zoom refits when one opens or closes. The toolbar shows or hides each panel, and Tab hides all of them and the menu bar to show the canvas at its real size. Which panels are shown and their sizes are saved for you and stay like that after restarting the game; Tab always starts off.
See: Layout editor · a button selected, Layout editor · panels hidden, Text editor · Text element with the placeholder list, Script editor · a long script and its minimap
46One snapping for everything
Moving and resizing snap to the grid, to other elements and to the screen's edges and center, for one element or many, with guides that show what lines up and which gaps are equal. Holding Alt skips snapping and shows distances instead. Grid sizes are in GUI pixels, the same units as the rulers and the Inspector.
See: Layout editor · moving with smart guides
47Number fields can be dragged
Dragging the label of a number field changes its value, the arrow keys step it by 1 and Shift+arrows by 10, and Enter or leaving the field applies it. The field still takes placeholder text with its { } button.
See: Layout editor · a button selected
48Animations live on a timeline
Everything that changes over time is animated on one timeline under the canvas: a track per element, a row per property, keyframes with their own easing, and a playhead that shows the real screen at that moment. Keyframes are added with a diamond next to the property, with K or by Auto-Key, never by recording.
See: Layout editor · editing a keyframe, Layout editor · animating a button
49Undo keeps your place
Every change is exactly one undo step, and undo and redo keep the selection, the scroll position and the open panels, so you can step back and keep working on the same thing.
See: Layout editor · today and proposed

Motion

50Icons stay still
Icons don't play animations on their own. Today, menu icons wiggle and submenu arrows spin whenever the pointer touches them, and all of that goes. An icon can still animate later where the motion is actually needed, but nothing moves just for decoration.
See: Context menus, Menu bar
51Menus grow in quickly
Top-level menus keep today's grow-in when they open, just as quick: 120 ms from 78 % size with an ease-out, starting from the corner they open from. Submenus open instantly. The animation never holds up a click or a key press, and it's skipped entirely when UI Animations is off or the UI theme doesn't allow animations.
See: Context menus, Menu bar
52Scrolling is smooth
Everything that scrolls, like context menus, lists, text editors and windows, glides to where you scroll instead of jumping a whole step at a time. Another wheel turn while it's still moving just moves the target further, so scrolling never waits for an animation, and content that loads while scrolling never makes the view jump. It has its own setting, Smooth Scrolling, next to UI Animations and on by default, because most people still want smooth scrolling with UI animations off. With it off, the UI scrolls in instant steps like today.
Requested in Keksuccino/FancyMenu#1839

Under the hood

53A clean API comes first
A clean and organized API matters most in the rework. When a part of the rework needs something the API doesn't have yet, like the pieces in rules 79 to 86, it gets added properly where it belongs, with one way for each job and the same names and shapes across all kinds, instead of a workaround in the UI code. The API may break for that: addons need an update, and there are no compatibility layers or deprecated leftovers for them. Only layout files from older FancyMenu versions have to keep working, and they load in the new version as they are (rule 55).
Applies to every rule in Under the hood and Fix during the rework
54The UI system gets rebuilt too
Everything in FancyMenu's current UI API and rendering system can be improved, reworked, cleaned up or replaced during the rework: UIBase and the UI themes, PiP windows, context menus, scroll areas, widgets like buttons and edit boxes, tooltips, the text and Markdown renderers, and the drawing helpers underneath. The goal is a clean, modern UI API that's easy to use for FancyMenu and addons alike, built once and shared by every screen (rule 1), and optimized, so big menus, long lists and live previews stay smooth. Like every other API, it may break addons (rule 53), and only old layout files have to keep working (rule 55).
Applies to every screen in this concept
55Only old layouts have to keep working
The rework may change any code and API without keeping the old one around. Addons are allowed to break and need an update, so there are no compatibility layers or deprecated leftovers for them. The one thing that always keeps working is layouts made with older FancyMenu versions. The rework is mostly UI and backend and doesn't change what gets saved in layout files, so they load as they are. Where something saved does change, FancyMenu reads the old form and converts it on load.
Applies to every rule in Under the hood and Fix during the rework
56Placeholders say where they work
Every placeholder says where it works, through a new method that returns one or more places from an enum, like everywhere, in a world or while a world loads. The UI uses it to explain why a value is empty right now, like the "in game" chip on file entries, and to show where each placeholder works in the placeholder list.
Full plan: Keksuccino/FancyMenu#1850
57Get Variable gets a shorter name
The display name of the Get Variable placeholder (fancymenu.placeholders.get_variable) changes from "Get Variable Value (FM Variable)" to "Get Variable" in every language file, so its chip stays short in the text editor. The identifier getvariable stays the same, so existing layouts keep working.
See: Text editor
58Placeholder variables get types
Placeholder variables are all plain strings today. Each variable gets an optional type from a new enum, like on/off, number, choice, element, file or server address. The editor then shows the right control for it, every variable gets parsed the same way, and nothing needs hint defaults anymore. Variables without a type stay plain text.
Full plan: Keksuccino/FancyMenu#1849
59Placeholder defaults are real values
A placeholder inserted from the list works right away. Hint defaults like slot_number or put_identifier_of_audio_element_here turn into real values, like the first fitting element of the layout, or stay empty when nothing fits. Variable types explain what goes into each variable, so the hints aren't needed anymore.
Full plan: Keksuccino/FancyMenu#1851
