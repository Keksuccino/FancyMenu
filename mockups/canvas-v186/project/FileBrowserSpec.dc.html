FancyMenu · UI rework concept · file browsers

One browser for every file you pick or save

Choosing a file, choosing a folder, saving a file and choosing a resource location all share one window: a toolbar to move around, a Places menu to jump to drives and recent folders, a list with thumbnails, and the same preview as the file entries in context menus. Only the bottom changes with what you are doing.

What gets in the way today
  • The path loses its start when it gets long, and there is no way back to a folder you just left.
  • Going up is a "Go Up" row in the list; there is no quick way to another drive or a folder you used a minute ago.
  • Files with names FancyMenu can't use are only explained in a tooltip, with no way to fix them here.
  • Dropping files into the window copies them, but nothing tells you that you can.
  • The main button says OK, and a file that already exists is only mentioned in a pop-up after you click Save.
The proposed browsers are the boards next to this one. Each is clickable: open folders, use the Places menu, search, type a file name.

The Places menu

Outside the game folder
When a browser may leave the game folder, the menu lists the drives with their free space, then recent folders and common places.
Limited to a folder
Most browsers stay inside a folder like FancyMenu's assets. No drives then, only recent folders inside it.
Resources
For resource locations, the namespaces take the place of drives, with where they come from.

Every browser

Choose File
Titled after what you pick: Choose Image, Choose Sound, Choose Video. Choose confirms; Apply uses the file right away and keeps the window open, where a live preview is possible.
Choose Folder
Lists folders only. The main button says Use This Folder, or Use and the folder's name when one is selected. The preview shows what is inside.
Save File
Adds a File name field with the fixed extension next to it. The main button says Save, or Replace when the name is taken.
Choose Resource Location
Namespaces are the top level, like drives. A Source column says where each resource comes from. Resources can't be changed, so there is no drop target, New Folder or Show in Explorer.
Choose Image Resource
The resource chooser that opens first: it picks between a local file, a Minecraft resource and a web address, and opens these browsers from Browse Files and Choose Location.

States

Dropped files
Minecraft only reports files once they're dropped, so the browser shows what happened right after: the new files are tagged New, the first one is selected, and the footer says where they went and what got skipped, with Undo. Dropping on a folder row copies into that folder (rule 118).
A name FancyMenu can't use
The file is marked and can't be chosen. The preview explains why and offers a fixed name; Rename also shows on hover in the list.
Saving over an existing file
The warning shows while you type, and the main button turns into a red Replace.
A file name that won't work
Capitals and spaces don't work in resource paths, so the field turns red and offers the fixed name.
Searching
Search looks in the open folder and every folder inside it. Matches from subfolders say where they are.
Video without Watermedia
The preview says it can't play videos and offers both downloads. Choosing the file still works.

Behavior

  • Double-click or Enter opens a folder or picks the file. Backspace goes up, Alt+Left and Alt+Right go back and forward, and typing starts a search.
  • The list follows the folder live: files added, renamed or removed outside Minecraft show up right away.
  • Recent folders are shared by all browsers and remembered between sessions. Drives only show up when a browser may leave the game folder.
  • A browser that is limited to a folder never shows anything outside it: the Places button names that folder and Up stops there.
  • Nothing in the browser is cut off: names and paths wrap in the preview.
