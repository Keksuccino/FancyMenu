FancyMenu · UI rework concept · Element editors

Edit it where you see it

Three elements send you to their own screen for part of their settings: the Audio element for its tracks, the Player Entity for its pose and the Block/Item JSON Model for its transform. All three move into the Inspector, next to the element's other settings, so the canvas stays in view and every change shows on the element right away.

What gets in the way
  • Manage Tracks is a full screen that replaces the editor, so you can't see the layout while you change its music.
  • Its list is plain text: the source type in brackets, the whole path and the weight. Nothing plays a track to check it's the right one.
  • Tracks move one step at a time with Move Selected UP and DOWN, and Remove Selected asks every time.
  • Set Weight Of Selected opens one more full screen for a single slider. Weights only matter in Shuffle mode, and they don't work: every track has the same chance, and a weight of 0 still plays.
  • Disable Vanilla Music in Screens isn't a setting. It opens a note that says where the setting is.
  • Entity Pose has 18 sliders in one long list, three for each of six body parts, and an Advanced Mode button next to every one.
  • The JSON Model's Transform window works the same way, and its ten light settings sit in a submenu.
  • Both windows cover the element they change.

The sections, piece by piece

Audio
Play Mode as In Order or Shuffle, Loop, Volume and Sound Channel like today. Vanilla Menu Music switches Minecraft's own menu music for every screen, so it carries the Global tag.
Tracks, in order
One row per track: a drag handle, the file name, a play button and the length. Hovering shows the preview card with the full path. A missing file says Missing in red, and the element counts as a problem in the status bar. Add Tracks opens the audio chooser.
Tracks, shuffled
The order doesn't matter anymore, so the handle makes room for a note icon, and the length for the weight: 1× is normal, 2× gets picked twice as often, .5× half as often, and 0 shows as Never.
Pose
A small figure with six parts to click: head, body, both arms and both legs. The picked part is filled, parts that are turned are tinted. Below it, X, Y and Z of that part from -180° to 180°, each with a reset arrow and the { } button.
Whole Body
Base Pose, like Standing or Crouching, Body Movement, Head Follows Mouse and Body Follows Mouse sit under the part rotations, since they pose the whole figure.
Transform and Lighting
View sets the rotation to one of four angles. Rotation and Offset have X, Y and Z, Size has Scale, and Model's Own GUI Transform is a switch. Lighting has the light color, the light rotation and the two lights.

Special cases they handle

  • Every change is one undo step in the editor, like any other Inspector change. The old windows changed the element live and saved one step on Done.
  • Removing a track doesn't ask. Undo brings it back.
  • A track whose length isn't known yet, like a link that hasn't loaded, shows no length.
  • Playing a track in the Inspector uses the element's Sound Channel and Volume, and stops when another one plays or the selection changes.
  • A rotation that holds placeholder text shows its chip instead of the slider, like every number row.
  • Mirror copies the picked arm or leg to the other side and flips Y and Z, so the pose comes out symmetric.
  • Right and left are the player's own sides, like in the old window, so the right arm is on the left of the figure.
  • With a rotation that fits none of the four views, View has nothing picked.

Changes beyond the UI

The sections above already use these, so each one is a rework rule.

Audio tracks sit in the Inspector New, rule 136
ManageAudiosScreen and SetAudioWeightScreen go away, and the audio chooser can return several files at once for Add Tracks.
Shuffle weights work New, rule 137
buildShuffleIndexesList builds a weighted pool and then keeps each track once, so the weights do nothing. The next track gets picked from the pool itself, and a weight of 0 leaves a track out.
A Player Entity's pose sits in the Inspector New, rule 138
PlayerEntityPoseScreen goes away. Mirror and Reset Pose are new, and Parrot becomes one setting in the UI while the layout keeps saving its two values.
A JSON Model's transform sits in the Inspector New, rule 139
JsonModelTransformScreen goes away, and the four views are new. They only set the three rotations.
The Inspector is the menu, docked Covered, rule 44
The three sections are ordinary Inspector sections, so they show in the element's right-click menu too.
Numbers with a range are sliders Covered, rule 17
Rotations run from -180° to 180° and get sliders. Offsets have no range and get number fields.
